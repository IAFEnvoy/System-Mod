# 模块全量清单与推荐优先级

整理日期：2026-11-19。实现基线：当前 `master`（Minecraft 26.1.2）工作区源码，包含尚未提交的修改。本文件是后续开发目录，不是发布版本的功能承诺，也不代表 1.21.1 已同步。

本清单完整覆盖[系统文功能调研](../research/system-novel-functions.md)中的 **22 类玩法、149 个细项**，另外列出建议独立落地的“收藏图鉴”，共 **23 类玩法候选**；经济、仓储、关系、卡片等基础能力另列。这里的“完整”指覆盖此次调研及当前项目能力，不表示穷尽所有小说和模组的设定。

原调研的来源编号、原文核验范围和 32 项“延伸”标记仍以原文件为准。下文的实现状态、模块划分和优先级是对本仓库的开发评估，不作为新增的原著设定证据。当前已实现并编译核对下述 P0／P1 增量、首批四项 P2 扩展、商城周期轮换与作业队列，以及通用多选一奖励、系统空间主动存入、固定交付委托和活动时间窗口，未启动游戏验收。2026-11-18 调整：抽奖累计奖励与重复补偿移至 P4，图纸研究移至 P3；下一批 P2 建议见第四节。

## 阅读方式

| 标记 | 含义 |
| --- | --- |
| ✅ 已实现 | 当前代码已经接入所列范围；不表示所属大类的所有设想都已实现。 |
| 🟡 部分实现 | 已有可用子集或联动，但表中列出的剩余流程仍需开发。 |
| 🧩 可配置 | 现有能力可以承载此类内容，仍需编写数据或接入具体事件；不算已有完整玩法。 |
| ⬜ 未实现 | 尚无对应完整业务流程；现有工具、action 或展示节点不能代替该流程。 |

| 优先级 | 建议 |
| --- | --- |
| P0 | 为选定玩法补必要的通用支撑，先于依赖它的扩展实施；按需要补，避免先造大框架。 |
| P1 | 优先开发：现有服务复用多、玩家收益明确、首版边界易收敛。 |
| P2 | 下一阶段：需要新的记录或规则，但能形成规模适中的完整流程。 |
| P3 | 中长期：涉及新的成长、对象或多人协作体系，宜分阶段实现。 |
| P4 | 远期／暂缓：包括世界模拟、实体 AI、领地、跨服等大型方向，以及明确后置的抽奖累计奖励与重复补偿；不一定代表工作量大。 |
| 维护 | 当前范围已有，继续修复与完善；不计入新增功能排期。 |

下文的优先级针对“下一步增量”，不是要求重做已有功能。工作量用“小／中／大／很大”作相对比较，不承诺具体工期。服务端负责真实数据、条件、扣费、结算与持久化；客户端负责展示和输入，AI 只提出操作意图，不能成为奖励、价格或完成状态的事实来源。

## 二、当前已实现的模块与基础能力

### 正式服务端模块

以下是当前 `SystemServerModules` 注册的 **21 个类型 ID**，不是某个数据包中的实例 ID。类型放在 `system:server_module`，带参数实例放在 `system:system_module`，系统定义引用实例或其 tag。

| 类型 ID | 状态 | 当前职责与边界 |
| --- | --- | --- |
| `system:core` | ✅ | 核心工作流、请求／工具装配、可信事实与共享里程碑领奖账本；不视为一个新玩法。 |
| `system:binding` | ✅ | 系统绑定、解除、模块启停与相关入口；当前一个玩家最多绑定一个系统。 |
| `system:usage` | ✅ | 用量查询及展示；不是游戏内经济账户。 |
| `system:player` | ✅ | 玩家信息快照与卡片；不是自建等级、资质或技能模型。 |
| `system:items` | ✅ | 物品查询、实际主手鉴定、获取来源；见 M09。 |
| `system:economy` | ✅ | 多币种钱包、管理员调整、系统币支付、货币 action／condition。 |
| `system:workshop` | ✅ | 报价后维修主手装备；见 M12。 |
| `system:online_jobs` | ✅ | 在线作业定义、材料投入确认、可配置串行队列、暂停与独立领取；见 M08。 |
| `system:anchor` | ✅ | 私人锚点、公共目的地、收费报价、动态容量与安全传送；见[传送锚点](teleport-anchors.md)。 |
| `system:signin` | ✅ | 每日奖励、固定循环、累计／连续／周月计数和里程碑；见 M02。 |
| `system:collection` | ✅ | 数据包系列、手动登记、进度／里程碑与独立领奖卡片；见[收藏图鉴](collections.md)。 |
| `system:inbox` | ✅ | 系统空间：通用内容类型、物品分页、单个／一组／语音取出；实体类型预留扩展。 |
| `system:shop` | ✅ | 系统商品购买、固定收购、周期限额与日／周／月库存轮换；商城与收购分别展示，多来源在同方向内合并，结算共用；见 M04 与[收购配置](shop-buyback.md)。 |
| `system:value_shop` / `system:value_buyback` | ✅ | Evaluate 无限出售／收购、可配置汇率及倍率、P90 出售上限、固定库存动态去重，仅搜索生成；见[无限交易](value-commerce.md)。 |
| `system:lottery` | ✅ | 加权抽奖、硬保底、连抽、限额、冷却、逐奖励获取次数上限及个人记录，支持物品与非物品奖励；见 M03。 |
| `system:achievement` | ✅ | 通用成就总览、系列统计、可信累计阈值和共用领奖；见[成就](achievements.md)。 |
| `system:advancement` | ✅ | 原版成就触发工作流；与数据驱动累计成就分开，世界首达仍待扩展。 |
| `system:commission` | ✅ | 原生固定交付委托，接取／放弃、材料报价与确认、周期次数和独立领奖；见[委托](commissions.md)。 |
| `system:ftb_quests` | ✅ 可选联动 | 任务查询与操作、通知、固定、说明书检索及可信完成积分；仅安装对应依赖时启用。 |
| `system:web_search` | ✅ 可选工具 | 搜索与网页提取、授权与计费；不自动赋予联网权限。 |

仍保留在 P2、暂不列入这批：有限离线作业收益（需先明确离线累计上限、停服是否计时、时钟回拨与模块禁用规则）；手动情报条目／线索库；收藏自动登记与搜索；更多可信成就事件；定向奖池。普通固定投入／产出的加工可先通过 online_job 数据完成，不单独再造生产模块。图纸研究为 P3，抽奖累计奖励与重复补偿为 P4。

## 五、后续实现应保持的边界

1. **模块按流程划分，数据按内容划分。** 奖池抽到灵兽／图纸／技能不是三个抽奖模块；不同币种不是多个经济模块；失败惩罚和返还倍率属于规则。
2. **先复用，再新增类型。** 维修、回收和分解优先扩展工坊；普通物品兑换优先用商城；收藏为成就提供事件；不要复制 FTBQ 的完整任务系统。
3. **数据驱动不等于任意字段都有效。** 当前正式数据包注册表为 `emotion`、`currency`、`online_job`、`system_module`、`system`、`signin_reward`、`shop_offer`、`lottery_pool`。另有 `collection`、`fact_reward` 支持收藏与可信事实领奖；研究仍是候选；私人锚点使用 system_module 配置，公共目的地使用 `teleport_destination` 注册表；将来新增注册表使用单数。
4. **结果必须服务端确定且可恢复。** 物品、系统币、经验、能力授予分别明确执行与交付语义；扣费前后要有可追踪状态，不能依赖客户端已显示某个卡片判断成功。
5. **AI 与联网保持可选。** 尽可能让玩法具有离线入口和确定性规则，AI 负责路由、说明与表达。网页工具维持“启用模块且本次明确允许”的规则；查询先使用有权限访问的本地知识。
6. **可选联动不污染必装数据。** FTBQ、宠物、技能、经济提供方等未安装时，不加载其类、不注册对应实现，也不让必须加载的内置定义引用缺失类型。
7. **存储按对象归属。** 玩家收藏、签到、作业放对应模块 DataStorage；世界首达和组织共享数据放适当的存档共享服务；知识数据库不承担所有经济事务。
8. **新功能同时提供可用交互。** 明确卡片、模块入口、界面内指令、工具入口、权限和双语文本；不能只有工具定义或只有一张空卡片就标记完成。
