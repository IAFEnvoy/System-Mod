# 对话执行模式与管理员 AI 权限

完整和简约界面在消息发送框左侧共用一个模式菜单。每项以大字显示名称、小字显示说明；默认**标准**。切换自动保存到服务端 PlayerData 的 `mode`，等待服务端确认后生效，重登保留。原来的外部 AI / 自由聊天两个开关和顶栏强制开关由此替代，历史保存仍在设置页独立控制。

## 四种执行策略

| 模式 | 文字请求的执行顺序 |
| --- | --- |
| 离线 `offline` | 明确指令 → 本地意图缓存 / 稀疏向量匹配 → 选项卡；不调用模型或服务端联网搜索 |
| 标准 `standard`（默认） | 明确指令 → 本地匹配 → 一次 AI 辅助路由 → 工作流或选项卡；AI 可服务于签到、知识整理等必要模块，不直接自由聊天 |
| 扩展 `extended` | 明确指令 → 较高阈值的本地匹配 → AI 辅助路由；模型无法选出能力时才进入一次自由回答 |
| 自由 `free` | 文字直接进入有界 ReAct 对话，由 AI 选择已启用的能力、观察结果并回答；跳过客户端指令、本地匹配及单独的 AI 路由步骤 |

`ConversationStrategy` 定义执行策略接口；`ConversationMode` 的四个枚举项各自实现 `route`，只安排共用 `Routes.local / assisted / chat` 步骤的顺序。`HybridRouter` 实现步骤，继续负责指令、候选、模型路由和本地选项。新增策略时不需要在路由器堆积模式分支。网络和存档使用枚举 Codec；新增内置模式时同步菜单、语言和权限语义。

结构化卡片按钮继续执行原有动作，不会被自由模式当作聊天。模式选择、历史开关等管理请求也不走模型。自由模式关闭文字指令补全；其他三种模式仍支持。`/ai on` 和 `/ai off` 分别切换标准和离线，全部四种模式使用菜单选择。

离线状态不会把依赖 AI 的工作流改造成另一套本地业务：例如需要模型选奖励的签到会提示当前模式不可用。语音识别和播报继续使用客户端个人开关和账号，与服务端对话执行模式独立。

`system-semantic.json` 的 `modeScores.functions=-0.1` 应用于离线和标准，`modeScores.freeChat=0.03` 应用于扩展。默认基础 score 0.9，分别得到 0.8 / 0.93；覆盖率、候选分差、只读限制、复杂句和参数解析条件仍然生效。模式参与缓存键，切换模式会清除该玩家的路由缓存并使旧执行失效。

## 管理员权限和同步

管理员权限独立于玩家偏好。服务端把当前玩家的 `allowAi`、`allowFreeChat`、`modelCallsPerDay` 和保存的模式同步到客户端，菜单根据相同规则禁用选项并显示灰色原因：

- AI 禁用或每日额度设为 0：只允许离线，当前执行降为离线。
- 自由聊天禁用：仅允许离线和标准，保存的扩展 / 自由偏好实际执行为标准。
- 管理员重新允许后，恢复仍保存着的原模式；玩家也可主动选择另一个允许的模式覆盖偏好。

客户端按钮不能修改管理员许可。服务端收到模式修改时重新检查权限，每次路由、模型请求和工具执行仍校验当前授权。每日已用次数继续在服务端扣减和判断；菜单的额度灰色条件是管理员配置为 0，并非客户端自行估算剩余额度。

管理员在原版聊天或控制台执行以下命令，需要权限等级 2。玩家参数接受单个在线玩家，支持原版名称 / 选择器补全，按 UUID 保存：

| 命令 | 作用 |
| --- | --- |
| `/system ai <玩家> enable` / `disable` | 允许 / 禁用 AI 及统一门禁下的服务端收费搜索 |
| `/system ai <玩家> freechat enable` / `disable` | 允许 / 禁用扩展和自由模式，不影响已获准的标准模式功能 |
| `/system ai <玩家> limit <次数>` | 修改每日模型调用上限；0 禁用模型模式，不清空已用次数 |
| `/system ai <玩家> status` | 查看有效权限和上限；可省略 status |
| `/system ai <玩家> reset` | 移除玩家覆盖，恢复继承 defaults，不清空个人偏好或已用额度 |

修改立即生效、自动保存。权限变化会取消在途交互、同步界面并发送原版聊天提示。配置为 `config/system/system-ai-access.json`，首次复制 JAR 默认文件；手动编辑后 `/reload` 生效，不受撤销绑定或清空历史影响。

```json
{
  "defaults": {
    "allowAi": true,
    "allowFreeChat": true
  },
  "players": {
    "00000000-0000-0000-0000-000000000001": {
      "allowAi": false
    },
    "00000000-0000-0000-0000-000000000002": {
      "allowFreeChat": false,
      "modelCallsPerDay": 20
    }
  }
}
```

示例 UUID 需替换为实际玩家 UUID。各项按“玩家覆盖 → defaults → 内置默认”解析。未配置的 allowAi / allowFreeChat 为 true；modelCallsPerDay 继续继承 `system-agent.json` 的 modelCallsPerPlayerDay。0 表示当天不再接纳模型调用。allowAi=false 同时关闭自由聊天与经统一外部服务门禁的收费搜索；本地工具、TTS 和 ASR 保持各自原有权限与账号配置。

设置页只读展示当前玩家的管理员许可及每日模型上限。客户端只能修改 history、mode 两项个人偏好，无法写入管理员配置或查看其他玩家的权限。

## 自由模式的功能调用和预算

核心工作流 `system:free_chat` 仍为 structuredOnly，普通模型意图路由不能自行选择它。扩展模式的兜底只生成一次回答。自由模式复用 `ReActLoop`：默认最多 6 轮、6 次模型、16 次底层工具、32 步、6 次写步骤、90 秒总期限，单次模型最多 30 秒。最后一轮只能回答；`system-agent.json` 的 `policies["system:free_chat"]` 可统一修改上限。

`ChatActions` 从已有 ModuleRegistry 取当前玩家可用、允许模型选择的工作流，将其 Codec / schema / description 绑定为本次循环的工具，支持已启用模块的参数化实例。显式入口标记继续提示模型谨慎使用；structuredOnly 的最终确认动作不进入目录。购买、抽奖等仍先返回原有确认卡，不绕过按钮。

嵌套工作流在同一个 Agent worker 和 ExecutionContext 内执行，不重新排队或获取自己的玩家执行锁。其 owner、来源、授权集合、策略和步骤前缀暂时隔离，结束后恢复；模型、工具、写入和总步骤共用计数，子策略只缩小余量及期限。每次调用分配独立写步骤前缀，避免多个工作流使用相同步骤名碰撞。循环保留真实结果卡及其按钮，失败 / 达到上限时也展示已获得的结果，不宣称失败操作已经成功。

联网仍通过原有知识问答工作流：先查本地数据库，空结果、已启用搜索模块且**当前请求明确允许联网**时才可搜索；不直接赋予自由聊天原始 Search / Fetch 工具。

历史开启时仅发送该玩家最近最多 20 条、合计 16 KiB 的适用文字；助手历史只取 ChatOutput 正文。历史、卡片和工具结果均作为不可信数据。回答使用 Markdown 卡片，复用历史、播报和统一 ModelGateway 用量计量。

## 扩展入口

`engine.chat().prompts(PromptProvider)` 可替换默认提示词提供者；默认文件 `data/system/system/prompts/free_chat.txt` 由 txt reload listener 加载，包含直接回答和 ReAct 协议。现有 `tools(ToolProvider)` 保留为底层 Tool 类型扩展接口，本次自由模式只自动装配已注册工作流，不读取该接口赋予原始工具权限。新增功能应优先注册工作流，复用所属模块、授权和确认语义。

本次只做编译和静态核对，未启动 Minecraft 或请求真实模型。菜单布局、鼠标 / 键盘操作及实际模型选工具仍需游戏内验收。
