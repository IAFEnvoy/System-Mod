# 活动时间窗口

`ActivityWindow` 是可复用的条目准入规则，不创建独立活动模块。它扩展现有 `EntryConditions`，所有使用共用条件的目录条目均能接入；商城、奖池、签到和委托提供时间状态展示。活动窗口只限制新增资格，不能撤销已经获得的权益。

## JSON 定义

写在商品、奖池、签到奖励、作业、委托等条目的根对象：

```json
{
  "activity": {
    "start_date": "2026-12-01",
    "end_date": "2026-12-31",
    "weekdays": [1, 3, 5],
    "hours": [
      { "start": "18:00", "end": "23:00" },
      { "start": "23:30", "end": "01:00" }
    ]
  }
}
```

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `activity` | 对象 | 始终开放 | 与 display_condition、condition 共同生效 |
| `start_date` | ISO 日期 | 无下界 | 可开放的首个起始日期，包含当天 |
| `end_date` | ISO 日期 | 无上界 | 可开放的最后起始日期，包含当天 |
| `weekdays` | 整数数组 | 全部星期 | 1＝周一，7＝周日，最多 7 项；空数组表示不限 |
| `hours` | 时段对象数组 | 全天 | 最多 16 段，空数组表示全天 |
| `hours[].start` | ISO 本地时间 | 必填 | 时段起点，包含 |
| `hours[].end` | ISO 本地时间 | 必填 | 时段终点，不包含；早于 start 表示跨午夜 |

日期支持 0001～9999 年，必须 start_date ≤ end_date；时段起止相同视为错误，需要全天时省略 hours。无效字段使数据包解析失败，不静默放行。不同日期／星期／时段条件取交集，同一天的多个时段取并集；重叠时段不会增加领取次数。

所有日期时间使用服务端 `system-agent.json` 的 `timeZone`，与签到、日／周／月限额一致，不接受客户端时钟。跨午夜时段归属**开始的日期与星期**：周五 23:30～次日 01:00 在周六 00:30 仍开放，最后一个 end_date 的跨夜时段也能延续至次日。夏令时交由 Java ZoneId 解析，不把自然日当作固定 24 小时。

## 各模块行为

| 来源 | 检查时机 | 活动结束之后 |
| --- | --- | --- |
| 商城／收购 | 预览、生成报价、确认扣费前 | 旧报价不能越过关闭时间成交，已付款物品仍可领取 |
| 奖池 | 预览、生成报价、确认扣费前 | 已抽取结果不变，原保底／限额计数保留 |
| 签到奖励 | 候选筛选、最终记账前 | 已获得的当日奖励仍可领取，不再次选择 |
| 在线作业 | 新作业开始前 | 已付费队列继续原有流程、完成和领奖 |
| 固定交付委托 | 新接取前 | 已接取按快照继续交付、领奖 |
| 其他 ConditionalEntry | 所属业务调用 CatalogAccess.usable/require 时 | 服从各自已获权益规则 |

`display_condition` 仍控制是否隐藏，activity 自身不隐藏条目。商城／奖池关闭的条目保留预览但禁用操作；列表 tooltip 和详情显示“尚未开始／开放中／当前时段未开放／已结束”，可再次开放时显示下次开放时间与业务时区。签到状态列出当前可见的限时奖励及开放状态，包括因离线估值筛选暂不进入候选的奖励。卡片展示的是查询时的快照，重新查询更新显示，服务端每次真实操作仍独立复核。

它与[库存轮换](shop-rotation.md)、周期限购和每日签到唯一性相互独立：窗口只决定是否开放，不更换库存、不重置额度、不另建每日签到账本。地点／维度准入继续组合 Saturn condition；可以按不同地点配置奖励，首版不新增打卡地图和事件日历界面。

只计算当前日期附近或未来开始日期附近的至多 9 天，寻找下一周的匹配时段，不扫描世界、不逐 tick 构建卡片。定义走原生数据包注册表，修改后需要重进世界／重启服务器；无需自建 reload listener。
