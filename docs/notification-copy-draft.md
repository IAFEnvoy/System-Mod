# 系统通知文案草稿

状态：已按本稿写入游戏内通知与礼包流程。日期：2026-10-27。

以下按“标题、正文、播报、按钮”分别列出。可以继续修改代码块中的句子，保留或移动 `{{占位符}}`；需要增加字段时，也可以先写上新的占位符。这里的占位符是文案标记，本文件不作为运行时模板加载；实际固定文案来自双语语言文件，布局字段来自类型化结果。

## 标题约定

所有通知左上角的黄色标题固定显示“系统”，不随系统名称或通知事件变化。它只作为界面的固定标识，不属于播报内容；无需按通知类型单独判断是否朗读标题。实际系统名称 `{{system_name}}` 和具体事件放在正文中，播报统一使用各场景的“播报”内容。

## 语气与参考

绑定部分参考了起点公开章节[《开局奖励新手礼包》第 1 章：叮！绑定系统](https://m.qidian.com/chapter/1024872894/0/)。已读取正文，其中的提示顺序是绑定、提示新手礼包、明确开启、告知获得内容；表达使用“叮”“宿主”和简短的状态宣布。下面的句子均为针对本模组重新拟写，任务部分按现有 FTB 状态设计，不是原文摘录。

统一采用简短的系统提示语气：事件先说清楚，再放任务要求、奖励等内容。减少“身份已确认、连接建立、权限已就绪、推进已记录、礼包回执”等日志用语。

文案中的“叮！”需要正常朗读，正文以“叮！”开头的场景，播报也保留这个开头，不因已有通知提示音而省略。连续通知仍沿用提示音只在首次展开时响一次的规则，但每条文案中的“叮！”照常朗读。没有“叮！”的场景不额外添加。新任务关闭详情播报时只读名称和奖励；开启后才追加要求与符合条件的背景，背景描述仍遵守描述开关，默认关闭。具体规则见“任务详情播报与服务端缓存”。

## 占位符约定

| 占位符 | 含义 | 示例或来源 |
| --- | --- | --- |
| `{{system_name}}` | 当前系统名称 | 系统定义 `name` 翻译后的文本，如“签到系统” |
| `{{system_description}}` | 当前系统介绍 | 系统定义 `description` 翻译后的文本 |
| `{{host_name}}` | 宿主名称 | 当前玩家显示名称 |
| `{{gift_list}}` | 新手礼包列表区域 | 列出当前玩家全部匹配礼包任务的奖励组；不展示任务名，内部保留对应任务 ID 与奖励 ID |
| `{{quest_name}}` | 任务名称 | FTB 任务标题 |
| `{{chapter_name}}` | 所属章节 | FTB 章节标题 |
| `{{quest_count}}` | 当前可推进任务数量 | 已解锁、可推进且未完成的普通任务数量 |
| `{{quest_list}}` | 任务列表区域 | 初次概览展示前三项；正式列表使用现有可滚动任务行 |
| `{{quest_requirements}}` | 任务要求 | 格式化后的目标及数量；特殊目标沿用现有整理与缓存 |
| `{{quest_description}}` | 任务描述 | 遵守 FTB 隐藏条件及用户设置 |
| `{{quest_background}}` | 可播报的任务背景 | 从 FTB 原有描述中筛选、整理的背景叙事；空描述、操作解释及无法判断的内容均省略，筛选结果缓存在服务端 |
| `{{quest_progress}}` | 真实任务进度 | 来自 FTB，不由模型补写 |
| `{{quest_rewards}}` | 奖励的可朗读摘要 | 如“火把十六个，面包四个” |
| `{{reward_items}}` | 奖励物品展示区域 | 现有物品小卡片及原版 tooltip，属于渲染槽位，不是重复的物品文字列表 |
| `{{submission_hint}}` | 手动提交提示 | 根据实际目标类型生成，见“手动提交提示” |
| `{{reward_notice}}` | 奖励状态短句 | 待领取、已领取或没有待领奖励；需要按玩家实际状态选择 |

字段没有内容时，连同对应标签整段省略，不显示空的“奖励：”“任务说明：”。`{{gift_list}}`、`{{quest_list}}` 和 `{{reward_items}}` 表示布局位置，其他占位符表示文本。事件载荷携带可见的要求、原始说明与奖励预览；播报按当前开关另行读取并校验权限。

## 01　初次绑定成功

触发：只有真正的新绑定成功。普通登录、重复 grant 和重新打开界面均不重播。

```text
标题
系统

正文
叮！恭喜宿主，{{system_name}}绑定成功！
宿主：{{host_name}}
{{system_description}}

播报
叮！检测到宿主，{{system_name}}绑定成功。{{system_description}}

按钮
打开系统 / 确定
```

以你给的系统定义和宿主 Steve 为例，完整效果：

```text
标题
系统

正文
叮！恭喜宿主，签到系统绑定成功！
宿主：Steve
本系统旨在每日给宿主提供各类道具和资源。

播报
叮！检测到宿主，签到系统绑定成功。本系统旨在每日给宿主提供各类道具和资源。

按钮
打开系统 / 确定
```

绑定通知不提前宣布礼包、签到奖励或可用模块。后续按照现有顺序单独展示：**绑定成功 → 可领取的新手礼包 → 当前可推进任务概览**。没有对应内容时跳过。预留的模块列表尚不控制功能，因此不写“签到与任务模块已开启”。

## 02　新手礼包待领取

触发：绑定引导中发现匹配的新手礼包任务，或后续有新礼包解锁。沿用现有新手礼包分类与 FTB 可见性条件，汇总当前玩家能找到的全部匹配任务，不只取第一个或前三个。

```text
标题
系统

正文
叮！宿主的新手礼包已准备就绪。
奖励：
{{gift_list}}
请宿主查收。

播报
叮！新手礼包已准备就绪，请宿主查收。

按钮
领取礼包 / 查看礼包 / 确定
```

所有匹配项汇总到一条新手礼包通知中，`{{gift_list}}` 为完整列表：每个匹配任务对应一组奖励，“奖励：”后换行显示物品小卡片，列表过长时滚动显示，不静默截断，也不按任务拆成多条通知。

礼包列表、详情和播报都不显示或朗读原始任务名，也不以章节名、任务 ID 代替。界面只呈现礼包内容及必要的领取状态；内部仍保留任务 ID、奖励 ID 和原生领取动作。同类物品跨任务保留各自奖励归属，不因展示汇总而合并领取语义。沿用当前分类：仅原生勾选、不可重复、全为可见固定物品奖励的任务才算礼包；经验、自选、混合或第三方奖励仍走普通任务展示和选择流程，不丢弃这些奖励。

“查看礼包”展开同一份完整列表，不返回带原始任务名的普通任务详情。“领取礼包”处理列表中当前可领取的奖励；暂不可领取或领取失败的显示实际状态，不触发物品或经验消耗。点击领取才显式提交礼包对应的原生勾选任务；查询与通知不提交。已经领取的条目不重复列为待领项；没有匹配项时跳过本通知。这里不写“已发放至背包”，点击领取后才调用原生领取流程。

新手礼包领取成功后静默处理：只刷新列表与领取状态，不再弹出“新手礼包已领取”通知，也不播报领取成功。部分领取时移除已领取项，保留待选择、失败或尚未领取的条目；全部处理完毕后继续后续通知。礼包相关的完成、领取回包也遵守此规则，不绕到普通任务成功通知重复提示。失败或待选择信息在原礼包列表中呈现，不伪装为领取成功。

## 04　新任务解锁

```text
标题
系统

正文
叮！新任务「{{quest_name}}」已解锁。
任务描述：{{quest_description}}
任务要求：{{quest_requirements}}
{{submission_hint}}
奖励：
{{reward_items}}

播报
叮！新任务「{{quest_name}}」已解锁，奖励{{quest_rewards}}。

按钮
查看任务详情 / 确定
```

上面的播报是关闭任务详情时的文案：只读任务名称和奖励，不读较长的 requirement、提交说明或任务描述。奖励沿用独立的奖励播报开关；关闭奖励播报或没有奖励时，连同“奖励”二字省略。播报使用文字摘要 `{{quest_rewards}}`，不能把物品渲染槽位 `{{reward_items}}` 直接交给 TTS。

开启任务详情后，先读名称，再按设置追加有效背景、任务要求和奖励；`{{quest_background}}` 只有在 FTB 原文确实包含背景叙事且描述播报已开启时才出现。原文为空、只有做法解释，或不能确定是否属于背景时，省略这一部分，仍正常播报任务名称和奖励，不跳过整条新任务通知。

```text
播报（任务详情与描述播报均开启，且确有背景）
叮！新任务「{{quest_name}}」已解锁。
{{quest_background}}
任务要求：{{quest_requirements}}
奖励：{{quest_rewards}}。
```

没有内容的整段连同标签、标点一起省略。显示区域仍可保留任务要求和 FTB 原始说明，语音开关及背景筛选只影响播报；原始说明仍遵守 FTB 的隐藏条件。非物品奖励保留对应展示与播报摘要，不能用物品卡片替代后漏掉经验、自选等奖励。

## 任务详情播报与服务端缓存

### 播报开关与背景筛选

- 任务详情关闭：只播报名称和奖励，不追加任务要求、背景或操作说明。奖励仍遵守独立的奖励播报开关。
- 任务详情开启：允许追加任务要求；背景还需开启描述播报，并且原文确有可讲述的背景，描述开关默认关闭。
- 背景指世界设定、人物动机、剧情、事件缘由等叙事。如何制作、收集数量、按键操作、提交步骤、机制解释、链接、重复任务标题均不算背景；不能仅按文字长度判断。
- 没有介绍或只含解释的任务不播报描述；混合内容只提取原有背景，说明部分留在界面里。不得为了让提示更像网文而补写原文不存在的剧情。
- 空白及明确无背景的内容直接跳过，不调用模型；需要语义判断或整理的原文才交给模型，结果不能确定时省略背景。

### 服务端缓存与调度

缓存已由服务端统一管理，保存到当前存档根目录的 `system-quest-backgrounds.json`，使用 FTB 任务唯一 ID 和语言定位，不按任务名称匹配，也不放入玩家附件。背景判定提示词为数据包资源 `system:quest_background`。

- 缓存任务的背景分类和最终可播报背景文本；空描述、纯解释、没有背景的结果也要缓存，避免每次通知重新判断。成功判定为“不播报背景”与模型请求失败必须分开记录，临时失败不能永久当成无背景。
- 同一任务按语言保存结果，并记录源内容指纹及判定提示词版本。原文、语言或判定规则变化时重新生成对应结果，不能只凭任务 ID 一直复用旧文本。
- 通知生成、查看详情等入口共用此缓存；同一任务的并发处理合并为一次生成，不同玩家使用相同语言时可复用同一份静态背景结果。
- 调度前先核对当前玩家的 FTB 可见性和描述隐藏条件；命中缓存不能绕过权限。客户端只拿到允许播报的结果，不接收隐藏描述。
- 缓存只保存静态描述的筛选结果，不混入玩家名称、当前进度、是否已领取、物品栏或具体领取结果。配置开关在实际调度时应用，关闭详情或描述播报后，即使已有缓存也不朗读背景。

## 手动提交提示

`{{submission_hint}}` 只根据实际目标生成，下面是可选句子，不同时全部显示：

| 目标类型 | 建议提示 |
| --- | --- |
| 需要消耗物品 | 包含手动提交目标，提交时将消耗对应物品。 |
| 需要消耗经验 | 包含经验提交目标，提交时将扣除对应经验。 |
| 勾选确认或原生手动按钮 | 包含手动确认目标，请宿主确认后提交。 |
| 仅限 FTB 界面或专用资源输入 | 部分目标需在 FTB 任务界面或对应输入中完成。 |
| 普通自动检测目标 | 不显示手动提交提示。 |

任务内任意一个目标符合原生手动提交条件，就归入手动提交任务；不能因此把同一任务中的自动检测目标也改成手动提交。需要指令提示时，可追加“提交时可发送「提交 {{quest_name}}」，或查询列表后使用编号。”，但仅适用于系统支持直接提交的目标。

## 本次改稿保留的行为

- 绑定 → 礼包 → 当前任务的队列顺序，以及普通登录不重播引导。
- 介绍性任务继续忽略，新手礼包保持独立领取入口；全部匹配项汇总为一个完整列表，不显示任务名。
- 新手礼包领取成功静默刷新，不追加领取成功或普通任务完成通知。
- 手动提交后已完成的普通任务只显示一次完成消息，不再显示提交成功或进度更新消息。
- 任务详情关闭时只读名称和奖励；背景只读原文确有的叙事，服务端按任务唯一 ID 缓存筛选结果。
