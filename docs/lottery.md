# 抽奖：保底、连抽、限制与记录

抽奖由服务端 `system:lottery_pool` 数据包注册表定义，文件路径为 `data/<namespace>/system/lottery_pool/<path>.json`。模块的 `pools` 字段仍支持 ID、tag 和混合数组。客户端只能预览并确认服务端报价，不能上传中奖结果、费用或保底进度。

页面和 `/lottery` 除奖池名称／ID 外，也可以按奖品的名称、tooltip、物品 ID 或 `#标签` 搜索。客户端使用原版物品搜索树提交带组件的有限候选，服务端只返回当前玩家可见且包含这些物品的奖池，匹配检查全部奖励，不局限于目录预览的十项。奖池上／下一批复用同一份搜索引用；「继续搜索」才切换下一批物品候选。搜索不会改变奖品、概率或抽取权限，详见[物品检索](item-search.md)。

```json
{
  "label": "补给奖池",
  "costs": [{ "type": "system:currency", "currency": "system:coin", "amount": 1 }],
  "draw_counts": [1, 5, 10],
  "pity": { "count": 10, "rewards": ["example:lottery/diamond"] },
  "draw_limit": { "count": 30, "period": "daily" },
  "cooldown": 2,
  "entries": [
    {
      "weight": 9,
      "reward": {
        "id": "example:lottery/food", "label": "食物补给",
        "items": [{ "id": "minecraft:bread", "count": 8 }]
      }
    },
    {
      "weight": 1,
      "max_wins": 2,
      "reward": {
        "id": "example:lottery/diamond", "label": "钻石补给",
        "items": [{ "id": "minecraft:diamond", "count": 1 }]
      }
    }
  ]
}
```

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `label` | 翻译键 / Component | 启用时必填 | 奖池名称 |
| `costs` | Saturn Cost 数组 | `[]` | 每抽费用；空数组表示免费 |
| `entries` | 奖品数组 | 启用时至少一项 | 奖品 ID 必须在本池唯一 |
| `entries[].weight` | 正整数 | `1` | 普通抽取的相对权重 |
| `entries[].max_wins` | 非负整数 | `0` | 每位玩家在本奖池获得该奖励条目的次数上限；`0` 不限，`1` 最多一次，`2` 最多两次，最大 2,147,483,647 |
| `entries[].reward` | 带 ID 的 Reward | 必填 | 支持物品、系统币、经验、action 和空奖 |
| `draw_counts` | 整数数组 | `[1,10]` | 可选连抽数量，1～100，每池最多 10 种，必须包含 1，不能重复 |
| `pity` | 对象 | 无保底 | 每玩家 / 奖池独立的硬保底 |
| `pity.count` | 整数 | 必填 | 最多连续多少抽必出指定范围，1～1,000,000 |
| `pity.rewards` | 奖品 ID 数组 | 必填 | 至少一项，必须引用本池奖品 ID，不能重复 |
| `draw_limit` | 对象 | 不限次数 | 每玩家 / 奖池的抽数上限，连抽按实际抽数统计 |
| `draw_limit.count` | 正整数 | 必填 | 一个周期内允许的抽数 |
| `draw_limit.period` | 字符串 | `lifetime` | `lifetime` / `daily` / `weekly` / `monthly` |
| `cooldown` | 整数秒 | `0` | 每次成功订单后的冷却，最长一年；整组连抽只启动一次冷却 |
| `display_condition` / `condition` | Saturn EntityCondition | 总是通过 | [展示与执行条件](catalog-conditions.md)，确认和支付前复核 |
| `enabled` | boolean | `true` | 是否启用 |

## 保底

上例表示：最多连续 10 抽内至少出现一次钻石补给。普通抽取命中该奖励也会重置计数；连续 9 次未命中后，第 10 次只在 `pity.rewards` 内按原相对权重抽取。保底范围可以有多个奖品，命中其中任意一项都重置计数。

十连逐抽计算，既可能提前命中，也可能在中途触发保底；后续各抽继续使用重置后的状态。卡片显示距离保底的最大抽数及目标奖励，公开奖品百分比表示基础概率，触发保底时使用保底范围内的概率。

进度以玩家 UUID 和奖池注册表 ID 保存，多个模块实例引用同一奖池时共用。重登、清空对话、移除再添加模块和订单归档均不重置；更换奖池 ID 是新奖池。修改保底阈值 / 目标时沿用已有未命中次数；较低阈值可能让下一抽立即保底。移除保底配置后，下一次成功抽取将未命中计数置零。没有保底的旧订单不追溯重算。

## 奖励获取上限

在奖品条目上设置 `"max_wins": 2`，即可让每名玩家在该奖池最多抽中该条目两次。省略或 `0` 表示不限次数，`1` 表示最多一次，负数无效。上例的钻石补给第二次抽中后从该玩家的候选中移除，之后只有食物补给；保底目标均达到上限后，保底暂停，不会卡住奖池。保底仍有可用目标时，仅在剩余目标中按权重抽取。

计数按玩家 UUID、奖池 ID 和 `reward.id` 隔离，统计整个奖励包的命中次数，支持物品和非物品结果。例如一次命中给 8 个面包，计为获得 1 次。不会检查背包已有物品；同一种物品放在不同奖励 ID 或不同奖池时互不影响，若想让一件物品只抽一次，请把它集中在一个 `max_wins: 1` 条目里。

所有成功命中都会计数，包括当时不限次数的条目。把上限从 1 提到 2 后，已获得一次的玩家还可获得一次；改为 `0` 恢复不限次，再改回正整数仍沿用历史计数。降低上限不会收回已得奖励，已达到或超过新上限的条目不再参与抽取。更换奖励 ID 视为新条目。

连抽逐次累计本组命中次数，达到上限后立即移除该条目，并重新归一化剩余权重。例如 `max_wins: 2` 且历史已获得一次，该连抽中最多再出现一次。若所有条目均有限额且剩余可命中次数之和不足以完成整组，服务端在扣费前拒绝，不自动减抽或补空奖；详情中对应抽数按钮禁用。目录 tooltip 展示初始概率，详情展示当前剩余候选的基础概率，各条目显示上限与已获得次数，达到上限的条目保留展示并标为 0%。未达上限时仍按原权重参与，不用剩余次数乘权重；保底可能改变单次实际概率。

只有成功结算或管理员核对为已支付时才累计获得次数；未领取到背包也算已获得，因为奖励权益已经生成。确认未支付的失败不占次数，支付未知时沿用同池阻塞规则，防止绕过。同一订单重试返回原结果，不重复累计。

每个奖励 ID 的累计命中次数保存在模块 DataStorage 中，独立于有界订单日志与归档。已有存档首次读取抽奖状态时，在存储线程从已结算活动订单和归档按逐抽结果补齐一次，归档与活动订单按订单 ID 去重，之后不重复扫描；保底进度不会追溯重算。重登、清空聊天、模块开关和订单归档不重置，撤销系统会清空业务数据。

## 连抽与结算

在详情中选择抽数，先预览该组总费用，再点击“确认支付并抽取 N 次”。`costs` 按单抽求值一次，绑定金额乘以抽数，不重复执行动态公式；目前没有连抽折扣。`/draw <奖池ID> [次数]` 或 `抽奖预览 <奖池ID> [次数]` 也只生成预览，仍需玩家确认。所有这些指令仅在系统界面输入。

整组共用一个报价、一个订单和一次支付。服务端先逐抽选择并持久化完整结果，再付款；相同物品及通用内容合并入系统空间，逐抽原结果与保底标记另行保留。个别空奖仍计一次抽取。若合并数量溢出、条目过多或空间容量不足，付款前拒绝；大批奖励可在空间按份领取，领取游戏效果仍沿用现有的单次执行上限。

确定未付款的失败不计保底、次数或冷却。付款未知时，整组继续占用次数，原奖励锁定，同一玩家对同一奖池的后续抽取暂停；不同奖池相互独立。管理员核对 `paid` 后解锁原结果并推进保底 / 启动冷却，`unpaid` 则释放次数，不推进保底。核对不重新抽取或扣费，见[订单维护](commerce-orders.md)。

## 抽取限制

每日零点、每周一零点、每月一日零点重置相应额度，使用服务端 `system-agent.json` 的 `timeZone`。累计限制不会周期重置。额度归属按预留订单时间计算，十连占用十次；剩余不足时拒绝整组，不自动改为较少抽数。免费奖池同样受限制。

保底与额度在玩家事务内检查、预留和提交；重复确认返回原结果，不重复占用。已归档订单通过带抽数权重的累计 / 近 35 天时间统计参与额度，修改商品式限额或时区仍按当前周期读取。冷却从成功结算时开始，结束后点击预览 / 刷新取得新报价。

## 抽奖记录

奖池目录、奖池详情及抽奖回执都有记录入口；系统输入框 `/lotteryhistory [奖池ID]` / `抽奖记录 [奖池ID]` 可查看自己的全部或指定奖池记录，离线模式可用。只查询当前玩家，不接收其他玩家 UUID。

列表按下单时间倒序，每批 20 个订单，批内使用通用网格本地分页。点击记录再加载该订单的逐抽结果，每批最多 20 抽，并支持返回记录列表。记录包含奖池、时间、抽数、状态、原奖励内容及哪些抽触发保底；未结算成功的预选结果不向玩家公开。

已归档记录与活动订单合并、按订单 ID 去重。归档中维护轻量时间索引，只解码当前页的完整订单；已有的无索引归档首次查询时在存储线程补索引。归档、查找与文件读取均在存储线程，游戏线程仅承担费用与奖励的游戏操作。撤销系统会清空这些业务记录。

完整数据包示例位于 [supplies.json](../examples/commerce-pack/data/example/system/lottery_pool/supplies.json)。非物品示例与条件仅放在 `src/test-mod/`，不进入发布 JAR。未启动游戏进行功能验收。
