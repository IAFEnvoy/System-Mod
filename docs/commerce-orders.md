# 商城与抽奖订单维护

商城购买和抽奖共用 `CommerceTransactions`。确认时先保存原商品 / 中奖奖励和价格快照、预留系统空间容量，再扣费；支付结果未知时锁定订单，不自动扣第二次，也不重新抽奖。

## 浏览分批加载

抽奖目录每批最多加载 128 个奖池，奖池详情每批最多加载 64 个奖品。超过时在卡片正文显示“上一批 / 下一批”和当前范围，点击后由服务端查询并替换同一卡片；目录查询词保持不变。每批内部仍使用通用网格的本地分页，只创建当前页的控件。

奖品概率始终使用整个奖池的总权重。翻批只是浏览，不扣费、不抽奖、不调用模型；奖池详情会重新求值费用和签发报价。同一玩家、类型、来源的新报价替换旧报价，旧确认卡片需刷新后再使用。报价有效期两分钟，确认和支付前仍检查目录版本及模块 / tag 权限。

## 自动归档

商城与抽奖各自保留活动订单账本。模块登录恢复及新订单预留时，账本达到 128 条便检查可归档记录，按时间归档较早部分，保留最新 64 条已结清订单：

- 确定失败、且没有关联权益的订单可以归档。
- 支付成功的订单必须已全部领取，权益为 `DELIVERED`，且系统空间没有对应剩余条目。
- 进行中的支付、支付未知、未领取、部分领取和领取结果未知均保留。自动归档不会释放这些权益或重发奖励。

完整订单写入独立的 GZIP 压缩 NBT，成功后才在同一玩家事务内删除活动订单及已领取权益、累计限购统计：

```text
<存档>/system/commerce/<玩家UUID>/<shop|lottery>/<账本代次UUID>/<订单UUID前两位>/<订单UUID>.dat
```

归档保存原价格、完整奖励及人工核对记录。重复点击历史确认 / 领取按钮时查询归档并返回原结果，不再次扣费或发奖；已归档成功订单显示已领取。写入归档后若玩家事务失败，下次可验证同一归档并继续，不重复累计限购次数。

限购统计由活动订单与已归档计数合并，按商品 ID 分开。归档计数保存累计次数和最近 35 天的精确下单时间，覆盖当前支持的每日 / 每周 / 每月周期，不因归档重置额度。商品先不限购、后来加限购时，历史次数仍参与统计。

抽奖连抽按实际抽数累计，而非订单数；近期时间戳带抽数权重。保底进度和冷却独立保存在抽奖模块数据中，不受订单归档影响。个人抽奖记录使用轻量时间索引分页读取归档，再合并活动订单；详见[抽奖规则与记录](lottery.md)。

活动账本的 4096 条上限及玩家文件容量限制保留；大量未结清订单仍可占满，不能靠归档绕过。归档 I/O 在存储线程执行。撤销系统时删除该玩家归档；新账本使用新代次，旧异步写入不能被重新绑定后的账本读取。

## 管理员指令

以下指令注册在原版聊天栏，需要游戏管理员权限，也可从服务端控制台使用。目标必须在线，`类型` 为 `shop` 或 `lottery`；玩家、类型及当前订单 ID 支持补全。

| 指令 | 作用 |
| --- | --- |
| `/system commerce list <玩家> <类型> [offset]` | 列出活动账本，每次最多 20 条，待核对订单优先，其他按时间倒序；offset 是从 0 开始的记录偏移 |
| `/system commerce show <玩家> <类型> <订单UUID>` | 查看活动或已归档订单，包括状态、来源、时间、原费用、奖励、错误及核对记录 |
| `/system commerce archive <玩家> <类型>` | 手动归档所有符合条件的已结清订单，不保留自动归档的最新 64 条 |
| `/system commerce resolve <玩家> <类型> <订单UUID> paid` | 确认原付款已成功，解锁原奖励，不额外扣款、不重抽 |
| `/system commerce resolve <玩家> <类型> <订单UUID> unpaid` | 确认原付款未成功，关闭订单并释放空间和限购占位，不自动退款 |

`list` 仅列活动订单；归档记录用已知 UUID 通过 `show` 查询。订单 ID 补全最多提供当前列表的前 20 条，优先待核对记录。

核对指令只接受 `PREPARED` / `PAYMENT_UNKNOWN`。管理员应先查看原费用并核对背包、钱包或外部支付记录：`paid` / `unpaid` 是人工判断，不会主动验证外部支付。核对人、决定与时间写入订单，并输出日志；已完成或失败的订单不能反复核对，已发布 / 已取出部分奖励的记录也会拒绝改写。

核对成功后，玩家可从系统空间或原回执领取已解锁奖励。此入口仅解决支付未知，不处理物品、经验、action 等已发生游戏效果的领取未知状态；MC 玩家数据和系统文件跨文件崩溃 / 回档时仍需人工核对，不能保证统一提交。
