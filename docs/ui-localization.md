# 界面与本地化

所有界面只加载 `assets/apricityui/apricity/system/assistant.css` 这一份共享样式。完整界面使用同目录下的 `assistant.html`，由 `AssistantScreen` 承载。使用青蓝半透明面板、细边框和暖金色重点色；布局重做为侧栏、查询/签到工具栏、对话结果卡片和输入区。

共享样式选取 AUI `t09-arwes-transparent` 及其 `t08-arwes` 基础主题中的透明表面、直角青色边框、内框、发光强调线、按钮交互和卡片侧边标记。完整界面、简约模式、HUD 消息和 AI / TTS 用量账本共用面板底色、边框、字体与按钮规则；布局差异通过 `body.simple`、`body.notification` 和 `body.usage` 调整，不再使用独立样式文件。样式已适配本界面的 ID/类名，不依赖外部工程路径；主面板保留较深底色，兼顾游戏画面透出和正文对比度。暖金色品牌与中文字体设置保留。

字体优先使用客户端已安装的微软雅黑 UI、微软雅黑、思源黑体/Noto Sans 和苹方，再回退到通用无衬线字体。结果正文为 14px，辅助说明至少 12px，标题和按钮使用 600 字重；提高文字亮度以改善深色半透明背景上的可读性。没有附带字体文件，不同操作系统的实际字形可能不同。

完整界面与简约模式通过 `AssistantInputScreen` 同步 AUI 输入框焦点和 Minecraft 26.1 的文本输入状态，避免游戏在每 tick 将输入法关闭。消息、物品搜索和商城搜索框都接入同一逻辑；失焦、关闭界面、切换模式或重建文档时释放文本输入状态，不强制切换系统语言。输入法预编辑文本使用 Minecraft 原生浮层，候选区域按 AUI 文档坐标转换到 GUI 坐标后定位在当前输入框附近；已确认的文字继续交给 AUI 的原有字符事件处理。

组合输入期间只由原生预编辑浮层设置候选区域，避免界面与浮层每帧提交不同矩形造成闪烁。未组合输入时只在输入框位置或 GUI 缩放变化后更新区域。AUI 的 `blur` 发生在焦点切换提交之前，因此等待切换完成后同步；不同可编辑输入框之间移动时保持输入法会话开启。

完整界面与简约界面的消息框均为单行 `<input type="text">`，打开时自动聚焦，Enter 或小键盘 Enter 与发送按钮共用一条提交路径；物品与商城搜索框的 Enter 分别触发对应搜索。按住 Enter 不会重复发送，等待响应或空白输入不清除草稿。原生输入法组合期间及结束后 150ms 内不执行发送、补全或方向键选项切换，确认候选时不失焦；补全弹层在组合期间隐藏。

`AssistantCommandSuggestions` 在客户端按前缀提供英文字指令、中文别名、`/system ` 前缀、开关参数以及当前回复中的选项编号和任务名称，不调用网络或模型；未接入 FTB 时隐藏任务类固定指令。`AssistantInputScreen` 只在消息框聚焦、光标位于末尾且没有文本选区时显示补全，每次展示最多 6 行；上下键切换，Tab 或点击只填写草稿，Enter 才执行，Esc 收起列表。弹层沿用唯一的 `assistant.css`；候选内容通过纯文本设置，点击补全恢复原输入焦点，不重启输入法会话。

简约界面使用 `assistant-simple.html`，由 `AssistantSimpleScreen` 承载：底部半透明说话框、当前请求、当前回复和输入区；沿用共享样式中的 Arwes 青色线框与易读中文字体。只读取客户端单独的 `current` 快照，不遍历对话列表，不加载历史；所有业务选项展平为连续编号，以 `选择 1` 或 `/select 1` 执行同一服务端动作。它只有发送按钮，其余功能使用文字或指令。

绑定提示、事件、服务端通知和界面关闭后的回复统一由 `AssistantMessages` 管理，使用 `assistant-message.html` 和同一份 `assistant.css`。通过 `Document.create` 注册普通 AUI 文档，由 AUI 自带的 HUD 层渲染；消息本身没有 `Screen`、输入框或额外渲染层，也不申请鼠标释放、输入焦点或输入法会话。页面背景全透明，面板宽度与简约界面同为 `min(840px,94vw)`，底部锚点同为 `6vh`。

正常游玩时整棵 DOM 禁用指针命中，按钮可见但不接受操作；进入原版 `ChatScreen` 后，使用 `body.notification.interactive` 仅开启面板及其后代的命中。模板使用 `aui-mouse-events=intercept`，因此只有命中面板才拦截原版鼠标事件，面板外点击与聊天输入仍保留默认行为。点击时清除 AUI 焦点，避免后续空格/Enter 被按钮吞掉；关闭聊天立即关闭指针命中并禁用按钮，保留同一文档和动画进度。提示从 `options.keyChat` 读取聊天键名，默认 T，用户重绑后自动更新。

启用语音输入后，可在通知完全展开时按住语音键（默认 F8）操作当前按钮，无需进入聊天栏；提示同时显示实际绑定键名。按钮使用固定本地化文案键，例句与缓存向量按当前按钮集合匹配，支持“确定”“关闭”“查看任务详情”“领取奖励”等；鼠标与语音共用同一执行入口。录音与等待识别时暂停倒计时，并在 `notification_voice` 显示状态及中间文字；不申请输入焦点。匹配不足或按钮歧义时打开主聊天并复用正常路由；动作忙碌时在通知内提示。隐藏、切换、确认和登出都会取消原通知的识别，详见[语音输入](asr.md)。

面板通过共享 CSS 的 `transform: scaleX(...)`，以水平中心为原点在 240ms 内向左右展开或收缩，不改变布局宽度和文字换行。标题、正文、按钮和提示统一放在 `notification_content`，以 160ms 的 opacity 过渡淡入淡出。`AssistantMessages` 以六个阶段管理顺序：隐藏、展开、淡入、可见、淡出、收缩，每步通过 AUI `Transition.isActive` 等待上一动画结束。首次打开先展开，再淡入；超时或确认先淡出，内容全透明后才替换为下一条并淡入，连续通知保持面板展开。队列清空时，淡出后再收缩并卸载；淡出期间收到的新消息直接接续，收缩期间收到新消息则反向展开后淡入。动画阶段不接受按钮交互、不扣除可见倒计时。鼠标事件每次文档 refresh generation 只注册一次，切换消息不重复挂载监听器。其他界面、F1、登出和显式清理仍即时隐藏或卸载，保留原有焦点及生命周期边界。

每条消息总有“确定”，绑定另有“打开系统”；业务通知从服务端结果提取最多两个可信动作，并可提供“查看详情”。确认会移除当前项，操作按钮移除后执行受信 Java 回调；业务动作保留原模块与输入，仍由服务端授权校验，助手忙碌时禁用。详情若属于当前回复则沿用当前模式，较早回复或事件打开工作台，以免替换简约界面当前选项。没有模型生成的 HTML 或可执行脚本。

任务列表的详情动作单独渲染在 `notification_choices`，逐行显示当前页的编号、名称、章节和进度，不占用底部两个业务按钮名额；底部保留“下一页”（如有）、“查看详情”和“确定”。列表沿用共享 CSS，按 T 后可滚动并点击任意一行，忙碌与动画阶段禁用；行操作仍引用对应的服务端可信动作，语音遇到同名详情动作时走原有歧义回退。消息去重同时比较行文案与动作，避免不同任务页因正文说明相同而被合并；切换通知时重置列表滚动位置。

通知框首次由隐藏进入展开阶段时播放原版注册音效 `system:notification`，结束后才开始正文播报；合成在提示音期间并行准备。连续通知只切换正文，收缩中途反向展开也不重复提示音，完全收起后下一轮才重新提示。提示音为播报音量的 75%，共用 Voice 分类与当前消息 session，关闭、隐藏或切换通知时同时停止。提示音不要求开启自动朗读或配置云端密钥；恢复通知和刷新文档不重复播放，详见 [语音合成与音色设计](tts.md)。

只有服务端成功持久化新绑定后才入队“宿主检测、连接建立、绑定完成”固定通知；不额外推理、不虚构初次绑定奖励，重复授予显示已绑定提示。队列依次播放、内容与操作相同的消息去重，最多等待 32 条，满载丢弃最早等待项。绑定显示 240 个可见客户端 tick，普通消息 160 tick；聊天栏内保留提示并暂停计时，其他界面或 F1 时卸载文档并暂停，恢复后重建并继续剩余时间，避免与简约界面重叠。资源重载后按文档 refresh generation 重新填充文本与按钮。若模板损坏，则回退到聊天消息并释放该项，避免逐 tick 重试。

正文最多 360 个 Unicode 码点和 6 行，面板限制高度且不滚动，长结果通过 `/system` 手动查看。事件与管理通知记入工作台会话，但不覆盖当前交互结果或其编号。客户端消息队列没有独立持久化或历史界面，登出、成功撤销时清理活动文档及等待项，撤销提示随后单独入队。

FTB 任务完成与新任务解锁复用同一 `event` 路径，使用 `system.result.quest_completed` / `system.result.quest_unlocked` 双语模板，卡片带任务标题、章节及既有 `system:quest_detail` 动作。完成通知按各玩家当前可领奖励增加固定“领取奖励”按钮：唯一普通奖励直接领取，多项或自选奖励显示选择详情。一个任务一条消息，完成项先入队、随后解锁项依次入队；不覆盖简约界面当前回复。详情及领取均可通过按钮或通知语音明确操作，沿用原有授权与引用校验。

仅在新绑定成功后，按“绑定消息 → 可领取的新手礼包 → 当前可推进任务概览”的顺序加入通知队列；多个礼包逐条显示，缺少礼包或任务时跳过。概览显示普通可推进任务的总数及前三项，用“查看任务”重新读取完整分页列表，不把已有任务逐条当作新解锁。重新登录、重复授予、换队或重载不重复触发引导，撤销后重新绑定可以再次触发。介绍任务从所有系统读取入口过滤；符合条件的勾选物品任务使用新手礼包卡片，沿用共享物品渲染、tooltip、通知动画和语音 session。通知提供“领取礼包”和“查看礼包”，已领取或不可领取时使用对应状态文案，不播报为可领取；礼包发现和领取回执只口播礼包名称，不逐项朗读物品。新解锁的礼包仍走相同展示，不重复发送其普通任务完成消息。

用量账本使用 `assistant-usage.html` 与 `TokenUsageScreen`：汇总卡片、按玩家排列的明细、刷新与分页，继续只加载 `assistant.css`。普通玩家仅查看自己，管理员可查看全服，服务端每次查询重新校验权限。统计通过独立网络载荷读取，不依赖绑定、不进入对话、不占用模型；统计口径与存档路径见 [AI / TTS 用量统计](token-usage.md)。

保留的是视觉风格。旧的绑定页、数据驱动功能列表、旧 HUD、世界窗口与旧完成弹窗没有继续使用。`/system` 打开后同步个人偏好；自动通知统一使用上述 HUD 消息，不抢占游戏焦点。

所有模型、玩家、FTB 和物品文本都通过 `setTextContent` 设置，不渲染模型 HTML/Markdown。固定空字符串 `setInnerHTML("")` 只用于清空容器。动作按钮和文字编号由 Java 根据业务结果创建，携带固定模块和输入；服务器仍重新校验。

对话、待响应请求、服务端偏好与能力、当前结果统一保存在不可变的 `AssistantClientState` 中，界面通过 `AssistantClient.state()` 读取；客户端登出或成功撤销时直接替换为 `EMPTY`，刷新版本号继续递增。`AssistantClient` 保留网络、导航和语音副作用，响应只投递给原连接代次。服务端历史和偏好按玩家读取；关闭窗口不回滚已经入账的奖励。输入区限制长度，等待期间不重复提交，但服务端仍独立限流。

完整界面的历史面板最多返回 24 条完整消息，超大结果仅保留装得下的完整卡片，整次响应另有限长；不会截断序列化 JSON。物品、任务、任务奖励和自选项均有分页动作，普通奖励按钮显示对应奖励名称。任务列表使用紧凑的编号行，只显示名称、章节与百分比；完整界面可点击行，简约界面可用“查看 1”或“查看 名称”。列表与候选页不显示嵌套目标和奖励，详情的说明、目标、奖励分别分页；有界详情不再受通用卡片 6000 字符截断影响。

完整界面的商城有侧栏入口、搜索工具栏、商品价格卡片和独立确认卡片；简约模式以文字和编号完成相同流程。每页最多 8 个商品。未启用系统币时显示支付未开放并隐藏购买动作；报价令牌不展示在卡片正文里。默认仅预留系统币支付，不显示虚构余额。

抽奖页与商城共用伸展搜索栏：输入框占满剩余宽度，搜索与全部奖池按钮等高且不被压缩；窄窗口时输入框单独占一行，按钮在下方均分宽度。辅助说明使用 12px 字号。奖池卡片突出名称、奖品种类和单次消耗，ID 降为次要文字；奖品卡片显示奖励名称、本地化物品名与数量、中奖百分比，不再堆叠权重和嵌套数据字段。完整界面通过类型注册选择卡片正文，简约模式和 HUD 共用对应的紧凑文字与物品预览；所有操作仍携带原来的可信动作，报价和独立确认流程不变。

`AssistantItems` 按类型注册物品投影，完整卡片、简约模式当前回复和 HUD 通知共用 AUI 原生 `<item>`。物品查询按注册表 ID 显示默认物品；签到候选、奖励与收件箱、商城商品和支付材料、抽奖消耗与奖品使用实际 `ItemStackTemplate`，保留自定义名称、附魔、耐久及其他组件。卡片按组显示图标、名称和数量，通知使用紧凑图标与数量角标，较多物品可以在按 T 进入聊天后滚动查看；空预览区域隐藏。图标跟随原文档布局、裁剪和淡入淡出，不增加独立绘制层或新样式文件。

物品模型通过共享 CSS 放大至原来的 1.75 倍，外层预留 40px 空间；单独增大 `<item>` 宽高不会改变 AUI 默认 16px 模型，因此对原生节点应用缩放。任务详情将普通物品奖励合并在“奖励：”标题的下一行，直接排列小卡片，物品名与数量不再在上方重复出现；领取状态移入各小卡片的次要文字。非物品奖励继续保留文字，自选奖励仍按候选分组。简约模式和通知的正文同样省去已由小卡片显示的普通奖励行；纯文本格式仍可单独获取完整摘要。

奖池列表额外显示首个奖品页的物品小卡片，每个物品保留奖励包名称及按整个奖池权重计算的概率；“奖品预览（已展示 / 总数）”按奖励包数量计数，完整内容继续通过“查看奖品与概率”分页。单次物品消耗只显示小卡片，免费和系统币金额仍为文字。详情页已有独立奖品卡片，因此不在顶部奖池信息重复预览奖品。签到候选统一放在候选奖励区，物品卡片附带所属奖励包名称；签到结果、抽奖结果及收件箱沿用奖励小卡片，商城商品和所需支付分组。简约模式与通知同样使用图标区域，奖品名称与物品列表不会在正文重复展开。

悬停图标通过 `GuiGraphicsExtractor.setTooltipForNextFrame` 提交原版物品提示，保留高级提示及 NeoForge tooltip 扩展。输入界面与 HUD 均使用原版延迟 tooltip 阶段；HUD 在聊天界面的 `Render.Foreground` 提前提交 AUI 界面状态，使随后提取的提示位于通知之上。AUI 自身按同一帧的 extractor 去重提交，不增加第二份界面绘制，也不重复处理输入法预编辑浮层。通知只有处于可交互的完整可见阶段才响应悬停，确认、切换或收起后不继续显示上一条物品提示；游戏操作期间不抢占鼠标。

FTB 详情和完成/解锁通知通过 Codec 同步普通物品奖励预览，沿用不可见及被阻止奖励过滤；详情中的自选项使用 `QuestChoiceOutput` 携带各候选名称与物品，保持分页、选项顺序和领取引用对应。`ItemPreviewOutput` 将显示数量与物品模板分开，FTB 基础模板取数量 1，数量角标直接使用 FTB 的固定值或随机范围，避免超大数量超过模板 Codec 的单栈范围。预览不触发发奖，不展开其他模组特有的非物品奖励，也不在通知中遍历整个自选奖池。

双语文件为 `assets/system/lang/en_us.json` 与 `zh_cn.json`，键集合必须完全相同。新增状态、字段或按钮需要同时维护两份文件。来自注册表的物品名仍受服务端语言影响，FTB 原始本地化组件尚无专门客户端翻译协议。

统一设置使用 `assistant-settings.html`，常规、语音播报和语音输入在同一文档内切换标签，仍只加载 `assistant.css`，复用 `AssistantInputScreen` 的原生 IME 生命周期；不带聊天输入框的页面不会注册消息补全或 Enter 发送。密钥使用 AUI 的 password 输入框，仅存本机。固定文本先在客户端翻译，再送入 TTS；语种默认跟随游戏语言，也支持自动或显式选择，Qwen3 使用 `language_type`，Qwen-Audio 使用 `language_hints`。播报页另有默认关闭的整句音频缓存开关。界面和当前通知各自持有语音 session：新回复替换旧朗读，关闭或切换界面即取消；通知超时、确认、操作或隐藏同样立即取消，不等语音播完再切换下一条。通知恢复和历史不重播，播放状态区分原版和 OpenAL 后备。中英文语言文件的键集合保持一致。具体参数、音色兼容与工具用法见 [语音合成与音色设计](tts.md)。

语音播报页的“合成语种”使用 AUI 原生下拉选择框，列出跟随游戏语言、自动识别及全部支持语种，选项名称使用客户端本地化。选择结果保留在表单草稿中，切换标签或导入音色后同步所选项，保存时写入原有语言字段；未填写 API Key 时沿用禁用逻辑。下拉框沿用唯一的共享 CSS 的字体、边框和焦点样式，弹出选项使用 AUI 原生弹层。

同页的“播报任务要求”“播报任务奖励”“播报任务描述”复用共享 `assistant_switch`，切换标签保留草稿，保存当前页后生效，默认开启要求与奖励、关闭描述。任务通知仅保留可信任务 ID，轮到当前语音 session 时按当前设置请求只读文案；模型整理回包不写入对话或替换卡片，不重置通知动画。任务要求、奖励和描述各有双语模板，物品名通过原版 Component 在客户端展开；可选目标与数量范围独立格式化，原有物品小卡片和 tooltip 不变。

系统文语气、提示词与公开参考来源见 [文案与提示词](system-voice.md)。UI 固定模板负责结算通知，模型只填写受限的签到选择理由；不会为语气额外增加模型轮次。

设置页的历史、外部 AI、自动朗读、音频缓存、语音输入和识别后立即发送统一使用共享 `assistant_switch` 拨动开关样式，包含滑块位移、开关配色、焦点和禁用状态。底层使用 `button type=button role=switch`，避免 AUI 原生 checkbox 绘制与轨道叠加；不再使用透明 checkbox 覆盖。`AssistantView.bindSwitch` 统一处理点击、禁用检查和状态切换，`switchChecked` 以 `aria-checked` 同时驱动样式、辅助语义和表单读取。按钮支持 Enter / Space 激活，轨道与文字不接收指针，整行按钮可点击；配置保存、导入和草稿逻辑不变。其他界面可复用同一结构与 CSS，不另加样式表。完整/简约模式仍使用分段按钮。

本轮仅检查模板结构、ID 绑定、资源路径与语言键，未运行游戏渲染。实际尺寸、滚动、输入焦点及不同 GUI 缩放仍需用户指定范围后进行客户端验收。
