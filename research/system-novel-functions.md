# 系统文功能调研与模块分类

调研日期：2026-11-12。用途：为 System Mod 后续玩法与数据驱动内容提供目录，本文件不代表已经实现的功能。

本次阅读了两篇系统流类型／创作资料，并核对了 16 部作品的官方简介或公开免费章节。范围包含传统系统流，以及相邻的玩家面板、诸天、领主、模拟器等机制；未进行全本梳理或出现频率统计。

上一版的 38 组、149 项是功能素材清单，不能直接当成模块清单。本版保留全部 149 项资料，区分玩法、通用机制、基础服务、内容定义和题材组合，并整理出 22 个独立玩法模块候选。模块边界是本次整理判断，不是原作的技术架构，也不表示每个候选必须对应一个实现类。

**依据标记：**来源编号对应文末实际阅读的页面。〔延伸〕仍表示本次未在所列原文中逐项核验的候选细分，共 32 项；创作资料中的例子不冒充具体作品设定。

## 分类标准

| 分类 | 判断标准 | 例子 |
| --- | --- | --- |
| 独立玩法模块 | 能独立启用，提供明确的玩家操作或持续玩法流程。可以依赖通用服务，不要求每项都有独立界面或专属存储。 | 任务、签到、抽奖、商城、模拟、宠兽养成。 |
| 通用机制 | 描述什么时候执行、需要付出什么、怎样计算、成功或失败后发生什么，由多个玩法复用。 | 条件、时限、消耗、奖励、惩罚、倍率、冷却、解锁。 |
| 基础服务 | 为系统和玩法提供统一的数据、生命周期或展示能力。 | 绑定、账户、仓储、状态面板、关系记录、通知。 |
| 内容定义 | 填入玩法与机制的数据，决定具体对象、参数和效果。 | 奖池、商品、礼包、功法、人物、宠兽、收益配置。 |
| 题材组合 | 用已有玩法、规则与内容组合出小说风格；有额外独立流程时再提取新模块。 | 厨神、学霸、宗门、神豪、末世、洞天。 |

**边界例子：**“任务失败扣 100 积分”属于任务的失败结果处理，复用扣款效果；不需要独立的失败惩罚模块。“抽到灵兽”是抽奖的奖励内容，只有后续需要训练、进化、寄养时，才涉及宠兽养成模块。

## 独立玩法模块候选

这里的子功能用于说明玩法范围。原文核验范围与延伸标记仍以随后逐项资料和来源表为准。

| 功能 | 子功能 | 介绍 |
| --- | --- | --- |
| 任务与委托 | 主线、支线、订单、向其他人发布委托 | 管理目标、进度、接受与完成；目标条件、奖励和失败处理复用通用机制。 |
| 签到 | 每日、地点、事件、连续累计 | 围绕签到记录、可领取状态与领取操作形成独立流程。 |
| 抽奖 | 选择奖池、付费抽取、结果领取 | 抽奖本身是玩法；抽物品、功法或灵兽归奖池内容，概率与保底归规则。 |
| 商城与兑换 | 浏览商品、购买、兑换、技能服务 | 管理商品与交易流程；商品内容、费用、限购和解锁规则分别配置。 |
| 成就与纪录 | 里程碑、首次达成、职业成就、收藏成就 | 维护持续达成记录，区别于需要接受和执行的任务。 |
| 属性成长 | 经验、等级、自由加点、资质调整 | 提供属性成长和分配操作；显示这些数据的宿主面板属于基础展示。 |
| 技能与职业 | 学习、熟练度、知识树、转职 | 管理能力的获得和成长；具体功法、技能与职业由内容定义提供。 |
| 挂机与训练 | 选择训练、持续消耗、收益积累、领取 | 适用于独立的训练或挂机流程；单纯每隔一段时间给奖励只需通用计时规则。 |
| 鉴定与分析 | 识别物品、分析目标、培养适配 | 宿主主动查询外部对象并取得信息；读取自己的属性不单独算鉴定玩法。 |
| 情报与查询 | 周期情报、机缘线索、人物内幕、主动查询 | 围绕情报的获取、查看和利用组织玩法；通知只是呈现方式。 |
| 制造与研究 | 图纸、配方、精炼合成、研发 | 管理知识、材料投入和产物；图纸和材料属于内容。 |
| 物品加工 | 强化、维修、改装、解封、回收分解 | 作为一组主动加工服务组织；孤立的升级、扣除或返材效果也可直接供其他模块调用。 |
| 宠兽养成 | 寄养、训练、培育场、孵化进化等候选 | 管理已有宠兽的持续成长；获得一个宠兽奖励不等于必须启用整套养成。 |
| 招募与随从 | 人物招募、兵种招募、名册、派遣 | 管理长期拥有的人物和单位；一次召唤或附身也可以只是奖励效果。 |
| 培养与返还 | 授徒、培养投入、成长反馈、投资返还 | 记录培养关系和投入成果，再按规则结算回报；倍率属于配置。 |
| 事业经营 | 店铺服务、产品、经营记录、周期核算 | 提供持续经营对象与过程；专款专用、亏损倍率等是附着的规则。 |
| 组织经营 | 成员、分工、组织目标、设施 | 管理组织及其成员；宗门是其题材实例，贡献值和组织商店复用账户与商城。 |
| 领地与军团 | 资源、建筑、领地成长、军队行动 | 管理区域建设和单位活动；末世避难所可使用其中的建设能力。 |
| 副本与挑战 | 关卡、世界任务、团队挑战、生存挑战 | 组织进入、过程、完成和退出；时限、评价、奖励及惩罚不是额外模块。 |
| 模拟与推演 | 人生、培养对象、战斗或经营候选推演 | 管理模拟输入、执行和结果；选择保留成果使用通用结算机制。 |
| 世界探索与传送 | 世界入口、跨界访问、探索与返程 | 提供目的地和行动流程；解锁条件、返程限制与时间比例是规则。 |
| 交易市场 | 玩家交易、跨界货物、服务订单、拍卖候选 | 管理不同主体间的交易；共享仓库等能力由基础服务支持。 |

## 通用机制如何复用

| 机制 | 作用 | 可以使用的玩法 |
| --- | --- | --- |
| 触发与条件 | 判断事件发生、对象符合条件、阶段已到或前置已完成。 | 任务触发、成就达成、地点签到、商品解锁。 |
| 目标与进度 | 统一检查数量、时长、关系或状态要求。 | 任务、挑战、训练、组织目标。 |
| 成本与额度 | 处理货币、物品、次数、时间等消耗或限制。 | 抽奖、商城、模拟、制造、传送。 |
| 结果与效果 | 发物品、加属性、改变关系、扣款或产生其他结果。奖励和惩罚都可通过效果表达。 | 几乎所有玩法的成功、失败、放弃与阶段回调。 |
| 时间与周期 | 时限、冷却、刷新、重置和周期结算。 | 签到、商店、任务、经营、挂机。 |
| 数量与随机计算 | 权重、概率、倍率、保底、补偿等计算；部分规则只由特定模块使用。 | 抽奖、返还、经营结算、随机奖励。 |
| 权限与解锁 | 限定宿主是否能访问某项能力或内容。 | 商城分级、世界入口、功法阶段、模块开放。 |

惩罚是结果的一种，不必单设一套玩法；“失败时执行哪些效果”应由拥有该失败状态的任务、挑战或模拟等玩法决定。通用机制也不等于每个机制都要拆成一个新框架。

### 通用机制（27 项）

这些条目附着在具体玩法上运行。例如失败判定归目标和时限，失败后扣款归结果效果。

| 功能／归属 | 子功能 | 介绍 |
| --- | --- | --- |
| 周期与重置 | 日常／重复任务 | 〔延伸〕按周期或条件重复产生目标，为持续获取资源提供稳定入口。 |
| 时限与失败判定 | 限时／挑战任务 | 要求在时限内达到数量、实力或行为目标，有时允许失败后重新挑战。[S11][S12] |
| 触发与条件 | 条件／事件触发任务 | 遭遇人物、危机或事件后才出现目标或选择，不需要固定时间刷新。[S07] |
| 条件与进度 | 收集／制作／交付 | 围绕指定物品组织目标；跨界订单可以要求收集特定物品。[S17]；制作与交付是可进一步拆出的目标形式。 |
| 条件与进度 | 击败／通关／生存 | 围绕战斗、世界副本或活过危险阶段组织任务。[S01] |
| 条件与进度 | 训练／学习／培养 | 按学习时长、学科内容或宠兽实力增长检查完成情况。[S11][S12] |
| 条件与进度 | 关系／经营／发展 | 目标也可以是好感度达到指定阶段，或围绕事业发展形成挑战。[S01][S12] |
| 结果与结算 | 固定奖励 | 完成后发放明确的经验、积分、道具或能力。[S10][S12] |
| 结果与结算 | 随机奖励／抽奖资格 | 任务本身不直接给最终物品，而是给一次抽奖机会或随机学科经验。[S12] |
| 结果与结算 | 选择奖励 | 面对不同选项走不同结果；奖励可以是技能，也可以伴随关系变化。[S07] |
| 结果与结算 | 结算保留 | 模拟结束后，从境界、武技、人生智慧中选择一项带回现实。[S08] |
| 随机与概率 | 空奖／概率分层 | 可以“谢谢参与”，也可以明确区分普通结果、样品、图纸等不同概率层。[S04][S12] |
| 抽奖规则 | 保底／定向池／重复补偿 | 〔延伸〕规定多次未中、重复抽取和定向目标的处理；不应把这些规则当成所有系统抽奖的默认机制。 |
| 解锁与权限 | 商城分级／权限解锁 | 新手、初阶、中阶、高阶等不同商城提供不同价位和层级的商品。[S10] |
| 解锁与权限 | 分层功能／商品解锁 | 系统可按层级提供资源与能力，已核验实例包括分级商城和功法后续篇章。[S10][S15] |
| 解锁与权限 | 系统升级／模块开放 | 〔延伸〕达到条件后增加系统功能、扩大额度或开放新的子系统。 |
| 供给与额度 | 刷新／限购／特殊商店 | 〔延伸〕改变供应时间、购买次数或进入条件，使兑换不只是永久商品目录。 |
| 状态变更效果 | 缺陷修复／潜能补全 | 系统修复宿主残缺的灵根等成长条件，使原先无法使用的能力可用。[S15] |
| 计时与收益 | 行为计时／挂机任务 | 持续待在图书馆等场所并满足行为要求，按时间和内容结算经验；不等于真正离线收益。[S12] |
| 计时与收益 | 躺平／被动获取经验 | 创作例：不行动也能按规则增长经验，甚至比主动活动收益更高。[S02] |
| 资金用途与额度 | 启动资金／专款专用 | 系统定期提供资金，但限定在合理经营活动中使用。[S03] |
| 结果选择与保留 | 境界／技能／经验保留 | 模拟不只给情报，还允许从几种成果中选一项变为现实收益。[S08] |
| 世界访问规则 | 世界解锁／返程／时间比例 | 〔延伸〕控制可进入的世界、返程资格与不同世界的时间关系，不能由“跨界”直接推定具体规则。 |
| 约束与结果 | 失败惩罚 | 任务失败后触发明确代价，不只是拿不到奖励；小说中的惩罚方式不必照搬到游戏。[S11] |
| 约束与结果 | 放弃成本／选择锁定 | 选定任务后不能随意更换，放弃需要支付积分，形成决策约束。[S12] |
| 约束与结果 | 资金用途／反作弊规则 | 明确禁止不符合目标的花钱方式，并限制通过简单漏洞绕过系统规则。[S03] |
| 约束与结果 | 绑定失效／保密要求 | 绑定条件不满足可能解除系统；部分系统还要求保守其存在。[S03][S11] |

### 内容定义（22 项）

奖励对象、商品种类和收益配置保持数据化。例如抽物品、抽功法、抽灵兽只是奖池内容不同；情绪值、贡献值的名称也不会自动产生新模块。

| 功能／归属 | 子功能 | 介绍 |
| --- | --- | --- |
| 礼包内容 | 新手礼包 | 首次绑定给予启动资源，可能包含道具、功法、经验或临时能力；也可能需要花少量贡献兑换。[S10][S15] |
| 任务编排 | 新手指导任务 | 用最初的任务引导宿主理解核心玩法，例如要求在限定时间内完成第一次培育。[S11] |
| 奖池内容 | 抽物品／装备／丹药 | 随机获得实物或消耗品；例如以负面情绪值抽取洗髓果实。[S04] |
| 奖池内容 | 抽功法／技能／天赋 | 〔延伸〕把随机结果设为可学习能力或成长资质，而不是背包物品。 |
| 奖池内容 | 抽灵兽／宠物／坐骑 | 〔延伸〕结果为可培养实体、宠物蛋或契约资格，后续接入宠兽养成。 |
| 奖池内容 | 抽人物／随从／英雄 | 直接获得可以为宿主效力的人物，结果内容可按武侠、高武、玄幻等分池。[S06] |
| 奖池内容 | 抽图纸／科技样品 | 奖励可以是可研究的样品或可制造的图纸，不只是成品。[S12] |
| 商品内容 | 物品／装备／材料兑换 | 用系统货币按价购买资源，与随机抽奖形成不同获取方式。[S01][S02][S10] |
| 商品内容 | 功法／技能／传承兑换 | 兑换能力或后续功法篇章，按成长阶段逐步开放。[S15] |
| 收益规则配置 | 负面情绪／怨念收集 | 他人产生负面情绪时计入收入，可显示来源人与数额，再消费这些情绪值。[S04] |
| 收益规则配置 | 展示实力／震撼反馈 | 以“装逼成功”等特定表现获得专用点数，再到商城消费。[S15] |
| 收益规则配置 | 使人发笑／正向情绪 | 创作例：让他人笑一次就增加经验，可用同一思路设计愉悦、赞赏等反馈。[S02] |
| 收益规则配置 | 善举／反套路行为 | 创作例：做好事、惹是生非、认输等特定行为也能触发成长或装备奖励。[S02] |
| 收益规则配置 | 消费／花钱返还 | 创作例：消费一定金额后得到更多资金，核心在“哪些消费算有效”。[S02] |
| 收益规则配置 | 亏损／逆向经营奖励 | 经营亏损与盈利采用不同财产转换比例，规则引导宿主追求与普通经营不同的目标。[S03] |
| 资质与体质 | 体质／血脉改善 | 通过系统奖励改变身体潜力；例如洗髓果实，或签到获得特殊体质。[S04][S05] |
| 能力定义 | 主动技能／法术 | 提供可主动施展的战斗、移动或生活能力。[S07][S18] |
| 能力定义 | 被动专长／抗性 | 提供专注、生命恢复、机械亲和、异常抗性等常驻或条件加成。[S18] |
| 限时能力 | 临时身份／能力体验 | 〔延伸〕用限时身份、附身或体验资格暂时获得另一套能力，与永久职业区分。 |
| 人物与能力奖励 | 临时召唤／附身 | 〔延伸〕只在指定时间或事件中使用人物能力，与永久随从区分。 |
| 关系阶段配置 | 忠诚／羁绊／关系奖励 | 〔延伸〕面向随从、队友或家庭记录长期关系，按阶段产生联动效果。 只有进一步形成送礼、互动、培养等独立流程时，才考虑增加关系养成模块。 |
| 组织资源配置 | 贡献资源／组织商店 | 用专用贡献值进入不同等级的商城，为组织成长供应资源。[S10] |

### 题材组合（8 项）

题材名称不直接决定模块边界。末世可组合建设、制造、挑战与情报；医疗和学霸可组合技能成长、任务、成就与研究。农场若有独立生产流程，则可再从组合中提取生产玩法。

| 末世与生存 | 生存装备／能源升级 | 从基础武器发展到高阶武器，从普通发电机发展到更先进的能源设备。[S13] |
| 末世与生存 | 周期灾难／备灾 | 按阶段面对酸雨、洪灾、冰川、辐射等危机，逼迫宿主提前建设和储备。[S13] |

| 职业题材 | 学科经验／科研奖励 | 按学习内容发放不同学科经验，并通过任务获得图纸或科技样品。[S12] |
| 职业题材 | 机械知识／技术制造 | 用主副职业、知识树、图纸和制造技能支撑工程成长。[S18] |
| 职业题材 | 厨艺／文娱／体育／种田 | 〔延伸〕将同一套“行为评估—进度成长—资源解锁”结构换成其他职业内容；本次未逐类核验作品。 |

| 2 | 物品加工：先做装备维修 | 对主手的一件装备报价，确认后支付配置费用并恢复耐久；第一版不做附魔重铸、随机强化或批量处理。 | 复用 Saturn Cost 和服务端主线程桥接；新增维修规则、目标快照、报价确认与操作回执。确认时重新核对物品及其状态，防止换手或重复点击造成错误扣费。 |
| 3 | 挂机作业：先做在线计时产物 | 选择一个采集／生产项目，在线累计有效时间，完成后手动领取物品。第一版只允许一个项目，退出或禁用模块时暂停，不累计离线收益。 | 复用模块玩家 Session、DataStorage、markDirty、收件箱发物品和卡片；新增作业定义、进度与领取状态。任务到时结算，不逐 tick 写文件。训练经验和技能成长后续再接。 |

“物品加工”和“挂机作业”可以独立启用。鉴定作为现有物品模块的新工作流，不为了多一个入口复制一整套模块定义。三项都应有本地指令／卡片入口，核心流程不依赖模型调用；未来可加入 AI 工具调用。

### 选型时的代码依据

- SystemServerModules 已注册签到、商城、抽奖、物品、成就触发、FTBQ 等实现，本轮不重复建设已有玩法。
- ItemQueryTool 目前按注册表检索，并用默认物品构建 ItemInfoOutput；不会读取玩家正在持有物品的真实耐久、附魔与组件。实际物品鉴定有明确增量，不是重写名称查询。
- ShopOfferEntry 已有 List<Cost> 和物品产出。因此“消耗指定物品换取另一种物品”的普通回收可以通过现有商城数据配置完成，暂不单独建立回收交易模块。批量选择与自动回收属于之后的新范围。
- CommerceCosts 已桥接 Saturn 的价格评估和付款；CommerceTransactions 和 PurchaseType 目前围绕 SHOP／LOTTERY 组织，维修不能假定可以直接使用现有购买流程，需要补充目标校验与回执衔接。
- PlayerModule.Session 提供模块启用期间的玩家 tick 与关闭钩子，ModuleData 和业务 DataStorage 已支持分模块持久化，适合承载一个有开始、进度和领取状态的在线作业。
- Reward 当前仅保存物品列表，DeliverTool 从收件箱发放物品。首版作业采用物品产物可直接复用；经验、属性、技能奖励需要另外补相应效果，不能宣称当前已经通用支持。

### 适合稍后做的候选

收藏图鉴／里程碑也可行，但需要额外定义收集表、历史登记、阶段奖励及领取记录，范围比只读鉴定更大。首版可先提供背包登记；若需要自动记录“曾经拥有”，还要补物品获得时的捕获与去重。

独立任务系统已有 FTBQ 集成可用，重建会涉及目标跟踪和提交语义；养成、随从、领地、诸天和人生模拟则缺少相应对象运行时。暂不作为低成本第一批。
