# FTBQ 开发任务集

`src/test-mod/ftbquests/quests/` 提供 **12 个章节、80 个任务**，格式对应当前 FTB Quests `26.1.2.8` 的 JSON5 文件。中文和英文标题、正文均单独放在 FTB 的 `lang/` 目录。这里只是开发用配置文件，不会打入发布 JAR，也不依赖模型 API。

## 安装与重新加载

在仓库根目录运行，需要 Python 3：

```powershell
python src/test-mod/ftbquests/install.py
```

默认复制到 `run-test-client/config/ftbquests/quests/`，**本次已复制**。FTBQ 不会自动读取模组资源中的任务文件，因此需要这一步显式安装。安装器只处理本目录内的文件，不删除其他任务；现有 `data.json5`、`chapter_groups.json5` 始终保留，缺失时才补默认文件。

为其他开发环境安装时传入 Minecraft 游戏目录（不是存档目录）：

```powershell
python src/test-mod/ftbquests/install.py --game-dir "D:/YourInstance/minecraft"
```

已有且修改过的测试章节/翻译默认保留，需要用仓库版本覆盖时加 `--overwrite`。此参数也不会覆盖已有的两份全局配置。所有新增章节文件均使用 `system_test_` 前缀，任务对象使用 `5A71` 开头的固定 ID；安装不会清理团队进度或重置已完成任务。

**推荐退回标题界面安装，再进入原来的测试存档。** 如果已在游戏内且具有 FTB 编辑权限，可以在安装后执行：

```text
/ftbquests reload quests
/system ftb reload
```

第一条让 FTB 读取磁盘任务并同步客户端；第二条让系统重新收录 FTB 当前已加载的说明书。只有第二条不会加载新章节。游戏中编辑的未保存内容应先保存，防止重载丢失。

确认测试系统启用了 `system:ftb_quests` 模块后，在系统对话框使用 `/quests` 打开列表，或从任务模块进入。已绑定玩家无需重新绑定；绑定时的新手礼包通知流程需要另外用授予/撤销操作复测，撤销会清除该玩家系统业务数据。

## 章节与覆盖场景

| 章节 | 任务数 | 主要用途 |
| --- | ---: | --- |
| 01 · 初来乍到 | 8 | 6 份新手礼包、1 份介绍、1 个普通任务；礼包跨任务合并相同物品和经验 |
| 02 · 资源仓库 | 25 | 无前置的物品检测任务；完整模式 2 页、通知 3 页，检查首尾页、固定三行、切换章节后页码与图钉 |
| 03 · 生存起步 | 4 | 自动检测物品与普通勾选任务，后者只有经验奖励，不应被归入礼包 |
| 04 · 物资上交 | 5 | 消耗物品提交、检测/提交/勾选混合、顺序目标、仅 FTB 原生界面提交 |
| 05 · 分支解锁 | 14 | 1 个前置、12 条同时解锁的支线、1 个双前置后续；检查解锁汇总和通知内分页 |
| 06 · 奖励陈列 | 6 | 经验、等级、多格物品、多种奖励组合、同类经验聚合、无奖励普通任务 |
| 07 · 文本与图标 | 4 | `§` 颜色/样式与逐行重置、超长标题、两行标题、叙事正文、不同原生图标 |
| 08 · 系统手册 | 4 | 无奖励的勾选/无目标说明书、带前置的隐藏说明书；不应出现在普通任务列表 |
| 09 · 独行试炼 | 1 | 单个普通勾选任务，检查少量内容不滚动、完成按钮与详情图钉 |
| 10 · 工具收藏 | 3 | 工具、武器、盾牌图标与 tooltip |
| 11 · 田园日常 | 3 | 少量同类收集任务、部分进度条 |
| 12 · 探索准备 | 3 | 水桶、船、末影珍珠等图标与小章节切换 |

所有任务仅使用原版物品，不要求额外内容模组。奖励关闭自动领取，便于检查领取按钮。物品目标的需求数量位于目标的 `count`；奖励物品数量位于奖励的 `count`，不是嵌套 ItemStack 的 `count`。这与当前 FTB 源码的读取方式一致。

## 建议的手动检查顺序

1. 打开 `/quests`，检查左侧只包含当前结果涉及的章节。系统手册中的介绍任务应被排除；切换到资源仓库，完整模式应为 18 + 7 项两页，通知内应为 9 + 9 + 7 项三页。最后一页与只有一项的章节仍保留三行区域及分页栏；只有一页时上下页均置灰。不要先收集整组资源，完成后任务会退出“进行中”结果。
2. 同一个任务在列表和详情分别点击图钉，确认方向和固定状态同步；点击图钉不应进入详情。切到单任务章节，检查无多余滚动。
3. 用 `/submittable` 查询可提交/勾选任务。在“上交 8 块圆石”中准备 8 块圆石，查看任务不会扣除，主动提交才扣除。混合任务即使有自动检测目标，也仍要手动操作；原生界面限定目标不能由系统代交。
4. 给自己 1 块圆石，提交“开启十二条支线”（ID `5A71050001000000`）。应将同时解锁的 12 项合为一条列表通知，内部可翻页、查看详情并返回；完成各任务仍应各有自己的完成通知。“木石交汇”只有两条指定支线都完成后才解锁。
5. 查看新手礼包并领取：6 份礼包每份有面包 2 个与经验 100，应合计面包 12 个、经验 600，其他物品单独展示。再次点击历史领取按钮应按现有幂等流程处理。
6. 查看“文本与图标”，检查颜色不会从上一行泄漏、长标题不遮图钉、图标不裁切。用 `/guide 任务图钉` 或 `/guide 主动提交` 检索说明书；隐藏说明只能在完成对应前置后查到。

这些是待游戏内执行的检查步骤。本次只生成、安装并静态检查文件，未启动 Minecraft、改变存档进度或实际验收交互。1.21.1 使用的 SNBT 格式不同，不能直接复制这套 JSON5 文件。
