# 轻量路由选型与后续计划

2026-10-24 重新按分发约束调整。当前实现见 [轻量本地意图路由](semantic-routing.md)：纯 Java 领域别名 + 稀疏 TF-IDF + 独立的精确意图缓存，低把握回退一次 DeepSeek。移除之前的 ORT、DJL、Caffeine、模型部署要求和相关配置示例，整个 System 产物在打包时限制为 10,000,000 字节。

## 资料核实与取舍

以下阅读公开 README、构建配置和项目文档得出；未复现性能、体积或准确率基准。来源的最新分支可能变化，不将样例模型大小推广到所有分类任务。

| 方案 | 核实与限制 | 当前选择 |
| --- | --- | --- |
| [JFastText](https://github.com/vinhkhuc/JFastText)、[构建配置](https://github.com/vinhkhuc/JFastText/blob/master/pom.xml) | 是 fastText 的 JavaCPP 包装，带平台 native 约束；README 的小型量化示例为语言识别模型，不能直接识别本项目业务模块。提供概率接口不等于业务置信度已校准 | 不默认引入。先有独立标注数据，再评估监督模型与完整平台依赖大小 |
| [fastText4j](https://github.com/linkfluence/fastText4j) | 纯 Java 推理实现，支持量化模型；README 声明兼容 fastText 1b 模型。mmap 需要转换成该项目特定格式，且 mmap 实现不支持多线程共享。这些能力不能直接套到 JFastText 或全部 Java 绑定上 | 将来可作为单独候选，需验证模型版本兼容性和维护成本 |
| [LIBLINEAR Java](https://github.com/bwaldvogel/liblinear-java) | 纯 Java，Java 11+，适合稀疏特征分类；需要本业务标签、特征流水线和训练。不是引入 JAR 就自动拥有分类能力；只有部分 solver 提供概率输出，仍需校准 | 有语料后优先评估，首版不附一个未经训练/验收的分类器 |
| 朴素贝叶斯 | 实现和模型均可很小，但也需要业务训练数据；主题相似而执行意愿不同的表达容易混淆 | 当前不额外增加一层未经评估的分类器 |
| “Similarity”词典工具 | 所给名称没有明确坐标/版本，不能确认具体项目、词典许可证及实际资源体积。“无模型”不等于词典和所有依赖很小 | 不把不明确的词典库打进发布包；维护本业务的小型中英领域词表 |
| TF-IDF / 字词相似度 | 不需要外部模型，词表、例句与稀疏特征可直接打包；能泛化已覆盖同义表达，复杂语义能力有限 | 当前采用，保留低分/小分差/低覆盖率回退 |
| MiniLM / TinyBERT + ONNX | 更换小模型并不能移除 native runtime 体积。英文 MiniLM 与多语版本不能混称，量化后大小和中文表现都要核对具体产物 | 不符合当前默认分发目标，未保留隐式下载路径 |

此前默认集成 ONNX 的问题不仅是发布 JAR 约 70.8MB，还要求管理员另外配置约 449MiB 模型权重。压缩模型或将权重外置不能解决“开箱即用、跨平台、轻量分发”的要求。新实现不依赖这些文件，也不要求部署 Redis、Python 服务或另一套向量 API。

## 当前节省 API 的位置

1. 保留已有明确短语、指令与结构化操作的零路由调用路径。
2. 领域别名与例句使常见自然表达在高分、足够分差和覆盖率时直接进入只读模块。
3. 成功的、可独立解析的部分 LLM 只读意图按玩家短期精确缓存，减少相同请求再次判意图。
4. 复杂、陌生、歧义与写操作意图保留 DeepSeek；签到奖励选择不改成缓存或随机逻辑。

这些是代码支持的路径，不是已测得的节省百分比。降低阈值虽然增加本地覆盖率，也可能增加误判；不以减少调用为由越过业务授权或静默丢弃参数。

## 后续评估

当前无需训练。先按模块/语言收集经同意使用的标注表达，区分“查询、执行、否定、条件、历史指代、混合请求、不支持”。词表/例句可以由管理员补充，不自动将玩家原文或模型判断写入全服公共样本。

用户明确要求测试后，分别评估独立校准集与验收集：本地直达覆盖率、误路由率、需要澄清比例、每类请求的远程次数，以及完整产物/内存/响应时间。不能把训练集命中、余弦分数、softmax 或未经校准的分类概率当成真实正确率。

如果调用成本仍高，再以同一语料比较 LIBLINEAR/量化 fastText。只有在“模型 + Java 库 + 平台资源 + 许可证 + 原模组”仍小于 10MB 且误路由可接受时才考虑接入；模型为经过评估的可分发资源，而非启动时自动训练或下载。这个可选监督后端尚未实现。
