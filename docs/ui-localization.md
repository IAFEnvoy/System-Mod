# 界面与本地化

所有界面只加载 `assets/apricityui/apricity/system/assistant.css` 这一份共享样式。完整界面使用同目录下的 `assistant.html`，由 `AssistantScreen` 承载。使用青蓝半透明面板、细边框和暖金色重点色；布局重做为侧栏、查询/签到工具栏、对话结果卡片和输入区。

页面初始化参考 MiXianTu 的 AUI 流程：`AssistantPages.prepare` 在创建文档前按实际视口预热模板引用的本地 CSS；仅等待 DOM 的 `readyState` 不足以等待外部样式。完整、简约、设置与用量界面共用 `AssistantPageScreen`，在文档上下文中完成监听器绑定、内容填充和首次布局提交后，才恢复自动渲染；窗口重建同样经过这条流程。绘制前先提交待处理样式与布局，再读取输入框坐标；补全弹层定位后再提交其变动，避免静止鼠标时继续使用旧位置。没有待处理布局时不强制重排，也不增加定时等待。HUD 通知复用样式预热，并在首次内容填充后提交隐藏状态布局，再开始原有展开与淡入动画。

HUD 通知使用视口固定定位，底边保持在 `6vh`，不再依靠自动高度面板的 flex 末端对齐；横向缩放动画只负责展开与收起。鼠标监听挂在通知面板上，仅聊天栏打开且当前通知完全可见时消费事件；每次刷新交互状态清除 HUD 键盘焦点，不可交互时清除按下状态，队列收起完成后移除文档。

针对 AUI 1.2.6 全局鼠标释放键不检查文档的行为，`AuiCursorReleaseMixin` 仅在其他活动 AUI 文档中存在可见、有尺寸的指针目标时允许释放鼠标；文档根节点、空 toast 容器和本模组通知均不算交互目标。空闲和只有通知时不因按左 Alt 而拦截游戏鼠标按钮，通知继续通过原版聊天栏交互。语音按键的保持状态与输入所有权分开：只有当前录音 session 尚未完成、仍活动且属于当前界面时才抑制字符，失焦或离开世界会清理保持状态。以上依据依赖源码及静态检查，未启动游戏验收。

助手名称和介绍来自当前连接同步的 `system:system` 注册表，完整界面的标题/欢迎区、简约界面的说话人/空闲介绍和 HUD 通知共用 `AssistantClient.system()`。两个字段都是翻译键，在客户端解析；绑定文案的参数依次为宿主名、系统名称和介绍，播报只读取宿主名及系统名称。数据包不会下发语言文件，自定义翻译需配套资源包，格式见[系统定义](datapacks.md#系统定义)。

共享样式选取 AUI `t09-arwes-transparent` 及其 `t08-arwes` 基础主题中的透明表面、直角青色边框、内框、发光强调线、按钮交互和卡片侧边标记。完整界面、简约模式、HUD 消息和 AI / TTS 用量账本共用面板底色、边框、字体与按钮规则；布局差异通过 `body.simple`、`body.notification` 和 `body.usage` 调整，不再使用独立样式文件。样式已适配本界面的 ID/类名，不依赖外部工程路径；主面板保留较深底色，兼顾游戏画面透出和正文对比度。暖金色品牌与中文字体设置保留。

字体优先使用客户端已安装的微软雅黑 UI、微软雅黑、思源黑体/Noto Sans 和苹方，再回退到通用无衬线字体。结果正文为 14px，辅助说明至少 12px，标题和按钮使用 600 字重；提高文字亮度以改善深色半透明背景上的可读性。没有附带字体文件，不同操作系统的实际字形可能不同。

完整界面与简约模式通过 `AssistantInputScreen` 同步 AUI 输入框焦点和 Minecraft 26.1 的文本输入状态，避免游戏在每 tick 将输入法关闭。消息、物品搜索和商城搜索框都接入同一逻辑；失焦、关闭界面、切换模式或重建文档时释放文本输入状态，不强制切换系统语言。输入法预编辑文本使用 Minecraft 原生浮层，候选区域按 AUI 文档坐标转换到 GUI 坐标后定位在当前输入框附近；已确认的文字继续交给 AUI 的原有字符事件处理。

组合输入期间只由原生预编辑浮层设置候选区域，避免界面与浮层每帧提交不同矩形造成闪烁。未组合输入时只在输入框位置或 GUI 缩放变化后更新区域。AUI 的 `blur` 发生在焦点切换提交之前，因此等待切换完成后同步；不同可编辑输入框之间移动时保持输入法会话开启。

完整界面与简约界面的消息框均为单行 `<input type="text">`，打开时自动聚焦，Enter 或小键盘 Enter 与发送按钮共用一条提交路径；物品与商城搜索框的 Enter 分别触发对应搜索。按住 Enter 不会重复发送，等待响应或空白输入不清除草稿。原生输入法组合期间及结束后 150ms 内不执行发送、补全或方向键选项切换，确认候选时不失焦；补全弹层在组合期间隐藏。

`AssistantCommandSuggestions` 在客户端按前缀提供英文字指令、中文别名、`/system ` 前缀、开关参数以及当前回复中的选项编号和任务名称，不调用网络或模型；未接入 FTB 时隐藏任务类固定指令。`AssistantInputScreen` 只在消息框聚焦、光标位于末尾且没有文本选区时显示补全，每次展示最多 6 行；上下键切换，Tab 或点击只填写草稿，Enter 才执行，Esc 收起列表。补全节点是 body 的直接子节点，使用独立 fixed 弹层，不参与输入区或面板的尺寸计算。候选重建时先隐藏，渲染阶段按输入框边界定位在其上方，使用所属文档的 CSS 像素并限制可用高度；位置未变化时不重复写样式。布局查询、物品 tooltip 与输入法热区计算都在 `Document.withContext` 作用域内完成，避免混用其他文档或窗口的视口尺寸。弹层沿用唯一的 `assistant.css`；候选内容通过纯文本设置，点击补全恢复原输入焦点，不重启输入法会话。

简约界面使用 `assistant-simple.html`，由 `AssistantSimpleScreen` 承载：底部半透明说话框、当前请求、当前回复和输入区；沿用共享样式中的 Arwes 青色线框与易读中文字体。面板使用 fixed 定位，水平居中、底边固定在 `6vh`，不依赖 body 的 flex 末端对齐，补全出现、收起或候选变化不会推动面板。只读取客户端单独的 `current` 快照，不遍历对话列表，不加载历史；所有业务选项展平为连续编号，以 `选择 1` 或 `/select 1` 执行同一服务端动作。它只有发送按钮，其余功能使用文字或指令。

绑定提示、事件、服务端通知和界面关闭后的回复统一由 `AssistantMessages` 管理，使用 `assistant-message.html` 和同一份 `assistant.css`。通过 `Document.create` 注册普通 AUI 文档，由 AUI 自带的 HUD 层渲染；消息本身没有 `Screen`、输入框或额外渲染层，也不申请鼠标释放、输入焦点或输入法会话。页面背景全透明，面板宽度与简约界面同为 `min(840px,94vw)`，底部锚点同为 `6vh`。

正常游玩时整棵 DOM 禁用指针命中，按钮可见但不接受操作；进入原版 `ChatScreen` 后，使用 `body.notification.interactive` 仅开启面板及其后代的命中。模板使用 `aui-mouse-events=intercept`，因此只有命中面板才拦截原版鼠标事件，面板外点击与聊天输入仍保留默认行为。点击时清除 AUI 焦点，避免后续空格/Enter 被按钮吞掉；关闭聊天立即关闭指针命中并禁用按钮，保留同一文档和动画进度。提示从 `options.keyChat` 读取聊天键名，默认 T，用户重绑后自动更新。

启用语音输入后，可在通知完全展开时按住语音键（默认 F8）操作当前按钮，无需进入聊天栏；提示同时显示实际绑定键名。按钮使用固定本地化文案键，例句与缓存向量按当前按钮集合匹配，支持“确定”“关闭”“查看任务详情”“领取奖励”等；鼠标与语音共用同一执行入口。录音与等待识别时暂停倒计时，并在 `notification_voice` 显示状态及中间文字；不申请输入焦点。匹配不足或按钮歧义时打开主聊天并复用正常路由；动作忙碌时在通知内提示。隐藏、切换、确认和登出都会取消原通知的识别，详见[语音输入](asr.md)。

面板通过共享 CSS 的 `transform: scaleX(...)`，以水平中心为原点在 240ms 内向左右展开或收缩，不改变布局宽度和文字换行。标题、正文、按钮和提示统一放在 `notification_content`，以 160ms 的 opacity 过渡淡入淡出。`AssistantMessages` 以六个阶段管理顺序：隐藏、展开、淡入、可见、淡出、收缩，每步通过 AUI `Transition.isActive` 等待上一动画结束。首次打开先展开，再淡入；超时或确认先淡出，内容全透明后才替换为下一条并淡入，连续通知保持面板展开。队列清空时，淡出后再收缩并卸载；淡出期间收到的新消息直接接续，收缩期间收到新消息则反向展开后淡入。动画阶段不接受按钮交互、不扣除可见倒计时。鼠标事件每次文档 refresh generation 只注册一次，切换消息不重复挂载监听器。其他界面、F1、登出和显式清理仍即时隐藏或卸载，保留原有焦点及生命周期边界。

每条消息总有“确定”，绑定另有“打开系统”；业务通知从服务端结果提取最多两个可信动作，并可提供“查看详情”。确认会移除当前项，操作按钮通常移除后执行受信 Java 回调；礼包领取保留当前列表并暂停等待期间的倒计时，由回包静默刷新，全部领取后才移除。业务动作保留原模块与输入，仍由服务端授权校验，助手忙碌时禁用。详情若属于当前回复则沿用当前模式，较早回复或事件打开工作台，以免替换简约界面当前选项。没有模型生成的 HTML 或可执行脚本。

任务列表的详情动作单独渲染在 `notification_choices`，逐行显示完整列表的连续编号、名称、章节和进度，不占用底部两个业务按钮名额；底部保留“查看详情”和“确定”，任务列表不再提供“下一页”。列表沿用共享 CSS，按 T 后可滚动并点击任意一行，忙碌与动画阶段禁用；行操作仍引用对应的服务端可信动作，语音遇到同名详情动作时走原有歧义回退。消息去重同时比较行文案与动作，避免不同任务列表因正文说明相同而被合并；切换通知时重置列表滚动位置。

通知框首次由隐藏进入展开阶段时播放原版注册音效 `system:notification`，结束后才开始正文播报；合成在提示音期间并行准备。连续通知只切换正文，收缩中途反向展开也不重复提示音，完全收起后下一轮才重新提示。提示音为播报音量的 75%，共用 Voice 分类与当前消息 session，关闭、隐藏或切换通知时同时停止。提示音不要求开启自动朗读或配置云端密钥；恢复通知和刷新文档不重复播放，详见 [语音合成与音色设计](tts.md)。

只有服务端成功持久化新绑定后才入队“叮！恭喜宿主，系统绑定成功”的固定通知，正文使用实际系统名称、宿主名称与系统介绍；左上角黄色标题始终为本地化的“系统”。播报保留“叮！”及实际系统名称和介绍，不读固定标题。不额外推理、不虚构初次绑定奖励，重复授予显示已绑定提示。队列依次播放、内容与操作相同的消息去重，最多等待 32 条，满载丢弃最早等待项。绑定显示 240 个可见客户端 tick，普通消息 160 tick；聊天栏内保留提示并暂停计时，其他界面或 F1 时卸载文档并暂停，恢复后重建并继续剩余时间，避免与简约界面重叠。资源重载后按文档 refresh generation 重新填充文本与按钮。若模板损坏，则回退到聊天消息并释放该项，避免逐 tick 重试。

正文保留完整内容，长文本、任务列表与物品列表在限定高度内分别滚动，不再按 360 码点或 6 行截断。事件与管理通知记入工作台会话，但不覆盖当前交互结果或其编号。客户端消息队列没有独立持久化或历史界面，登出、成功撤销时清理活动文档及等待项，撤销提示随后单独入队。

FTB 任务完成与新任务解锁复用同一 `event` 路径，使用 `system.result.quest_completed` / `system.result.quest_unlocked` 双语模板，卡片带任务标题、章节及既有 `system:quest_detail` 动作。完成通知按各玩家当前可领奖励增加固定“领取奖励”按钮：唯一普通奖励直接领取，多项或自选奖励显示选择详情。一个任务一条消息，完成项先入队、随后解锁项依次入队；不覆盖简约界面当前回复。详情及领取均可通过按钮或通知语音明确操作，沿用原有授权与引用校验。

已解锁且未完成、剩余目标全为原生勾选目标的任务，在解锁通知和详情卡片增加固定“完成此任务”动作，简约模式同样列入编号选项。通知语音例句按 `system.action.complete_quest` 注册；点击与语音共用 `system:quest_submit` 的仅勾选模式，由服务端重新检查当前条件，不消费物品或经验，不跳过真正锁定的前置任务，完成后只显示原有完成通知。

仅在新绑定成功后，按“绑定消息 → 可领取的新手礼包 → 当前可推进任务概览”的顺序加入通知队列；全部匹配礼包汇总为一条通知，缺少礼包或任务时跳过。概览显示普通可推进任务的总数及前三项，用“查看任务”重新读取完整滚动列表，不把已有任务逐条当作新解锁。重新登录、重复授予、换队或重载不重复触发引导，撤销后重新绑定可以再次触发。介绍任务从所有系统读取入口过滤；符合条件的勾选物品任务按来源分组呈现全部奖励，不展示或播报来源任务名、章节或 ID，沿用物品渲染、tooltip、滚动和语音 session。“查看礼包”读取同一完整列表，“领取礼包”按可信引用批量处理；成功后静默更新，移除已领取项，失败保留在列表中，不追加成功提示或普通任务完成通知。新解锁礼包按每批每玩家汇总一次。

用量账本使用 `assistant-usage.html` 与 `TokenUsageScreen`：汇总卡片、按玩家排列的明细、刷新与分页，继续只加载 `assistant.css`。普通玩家仅查看自己，管理员可查看全服，服务端每次查询重新校验权限。统计通过独立网络载荷读取，不依赖绑定、不进入对话、不占用模型；统计口径与存档路径见 [AI / TTS 用量统计](token-usage.md)。

保留的是视觉风格。旧的绑定页、数据驱动功能列表、旧 HUD、世界窗口与旧完成弹窗没有继续使用。`/system` 打开后同步个人偏好；自动通知统一使用上述 HUD 消息，不抢占游戏焦点。

所有模型、玩家、FTB 和物品文本都通过 `AssistantView.text/element` 写入纯文本节点，不渲染模型 HTML/Markdown。固定空字符串 `setInnerHTML("")` 只用于清空容器。动作按钮和文字编号由 Java 根据业务结果创建，携带固定模块和输入；服务器仍重新校验。

FTBQ 标题、章节、说明、目标及奖励中的原版 `§` 格式和 FTB 常用的 `&` 格式由共享 `AssistantText` 处理，完整界面、简约模式、HUD 正文及任务按钮共用一条路径。FTBQ 服务端标题保留原始文字，未进行客户端富文本解析；`LegacyText` 先把有效的 `&0`～`&f`、`&k`～`&o`、`&r` 转成原版格式码（大小写均支持），保留未知码和转义的普通与号，再复用原版 `StringDecomposer.iterateFormatted`。显式换行后从空样式重新解析，颜色和粗体等只影响当前行；同一行因宽度自动折行时继续保留格式。任务列表的标题、章节以及目标、奖励名称等独立字段通过 `LegacyText.scoped` 在拼接边界追加重置码，分隔符、编号、进度与状态恢复界面默认样式。按连续样式创建固定 `span` 节点并设置颜色、粗体、斜体、下划线及删除线；`§r` / `&r` 恢复当前界面的默认样式，不强制黑色。混淆样式不生成随机乱码，其他无效或末尾不完整的 `§` 格式码按原版解析规则处理。正文、换行和 Unicode 字符仍通过 `setTextContent` 写入，任务文本中的 HTML 标签只作为文字显示。格式节点保持行内布局和原按钮点击目标，不新增样式文件。TTS 使用同一转换入口提取纯文本，不朗读这两类控制码。

对话、待响应请求、服务端偏好与能力、当前结果统一保存在不可变的 `AssistantClientState` 中，界面通过 `AssistantClient.state()` 读取；客户端登出或成功撤销时直接替换为 `EMPTY`，刷新版本号继续递增。`AssistantClient` 保留网络、导航和语音副作用，响应只投递给原连接代次。服务端历史和偏好按玩家读取；关闭窗口不回滚已经入账的奖励。输入区限制长度，等待期间不重复提交，但服务端仍独立限流。

完整界面的历史面板最多返回 24 条完整消息，超大结果仅保留装得下的完整卡片，整次响应另有限长；不会截断序列化 JSON。对话滚动容器和每条消息使用普通块布局，长卡片按完整内容占位；消息间距由外边距控制，避免嵌套纵向 flex 测量导致后续消息进入上一张卡片。物品、任务详情中的奖励和自选项保留分页动作，任务列表及名称候选列表改为完整滚动列表，普通奖励按钮显示对应奖励名称。任务列表使用紧凑的编号行，只显示名称、章节与百分比；完整界面可点击行，简约界面可用“查看 1”或“查看 名称”。列表与候选列表不显示嵌套目标和奖励，详情的说明、目标、奖励分别分页；有界详情不再受通用卡片 6000 字符截断影响。

完整界面的商城有侧栏入口、搜索工具栏、商品价格卡片和独立确认卡片；简约模式以文字和编号完成相同流程。每页最多 8 个商品。价格使用服务端求值后的 Saturn Cost 快照，单物品费用显示图标，资源、标签与其他费用使用文字；无法生成账单时隐藏购买动作。报价令牌不展示在卡片正文里，不显示虚构余额。

抽奖页与商城共用伸展搜索栏：输入框占满剩余宽度，搜索与全部奖池按钮等高且不被压缩；窄窗口时输入框单独占一行，按钮在下方均分宽度。辅助说明使用 12px 字号。奖池卡片突出名称、奖品种类和单次消耗，ID 降为次要文字；奖品卡片显示奖励名称、本地化物品名与数量、中奖百分比，不再堆叠权重和嵌套数据字段。完整界面通过类型注册选择卡片正文，简约模式和 HUD 共用对应的紧凑文字与物品预览；所有操作仍携带原来的可信动作，报价和独立确认流程不变。

`AssistantItems` 按类型注册物品投影，完整卡片、简约模式当前回复和 HUD 通知共用 AUI 原生 `<item>`。物品查询按注册表 ID 显示默认物品；签到候选、奖励与收件箱、商城商品和支付材料、抽奖消耗与奖品使用实际 `ItemStackTemplate`，保留自定义名称、附魔、耐久及其他组件。卡片按组显示图标、名称和数量，通知使用紧凑图标与数量角标，较多物品可以在按 T 进入聊天后滚动查看；空预览区域隐藏。图标跟随原文档布局、裁剪和淡入淡出，不增加独立绘制层或新样式文件。

物品模型通过共享 CSS 放大至原来的 1.75 倍，外层预留 40px 空间；单独增大 `<item>` 宽高不会改变 AUI 默认 16px 模型，因此对原生节点应用缩放。任务详情将普通物品奖励合并在“奖励：”标题的下一行，直接排列小卡片，物品名与数量不再在上方重复出现；领取状态移入各小卡片的次要文字。新手礼包通知只显示物品图标与数量角标，不附加“可领取”或“暂不可领取”状态文字；领取失败时仍显示对应错误。非物品奖励继续保留文字，自选奖励仍按候选分组。简约模式和通知的正文同样省去已由小卡片显示的普通奖励行；纯文本格式仍可单独获取完整摘要。

奖池列表额外显示首个奖品页的物品小卡片，每个物品保留奖励包名称及按整个奖池权重计算的概率；“奖品预览（已展示 / 总数）”按奖励包数量计数，完整内容继续通过“查看奖品与概率”分页。单物品消耗只显示小卡片，免费和其他 Cost 使用文字；混合费用同时显示图标和文字。详情页已有独立奖品卡片，因此不在顶部奖池信息重复预览奖品。签到候选统一放在候选奖励区，物品卡片附带所属奖励包名称；签到结果、抽奖结果及收件箱沿用奖励小卡片，商城商品和所需支付分组。简约模式与通知同样使用图标区域，奖品名称与物品列表不会在正文重复展开。

悬停图标通过 `GuiGraphicsExtractor.setTooltipForNextFrame` 提交原版物品提示，保留高级提示及 NeoForge tooltip 扩展。输入界面与 HUD 均使用原版延迟 tooltip 阶段；HUD 在聊天界面的 `Render.Foreground` 提前提交 AUI 界面状态，使随后提取的提示位于通知之上。AUI 自身按同一帧的 extractor 去重提交，不增加第二份界面绘制，也不重复处理输入法预编辑浮层。通知只有处于可交互的完整可见阶段才响应悬停，确认、切换或收起后不继续显示上一条物品提示；游戏操作期间不抢占鼠标。

FTB 详情和完成/解锁通知通过 Codec 同步普通物品奖励预览，沿用不可见及被阻止奖励过滤；详情中的自选项使用 `QuestChoiceOutput` 携带各候选名称与物品，保持分页、选项顺序和领取引用对应。`ItemPreviewOutput` 将显示数量与物品模板分开，FTB 基础模板取数量 1，数量角标直接使用 FTB 的固定值或随机范围，避免超大数量超过模板 Codec 的单栈范围。预览不触发发奖，不展开其他模组特有的非物品奖励，也不在通知中遍历整个自选奖池。

双语文件为 `assets/system/lang/en_us.json` 与 `zh_cn.json`，键集合必须完全相同。新增状态、字段或按钮需要同时维护两份文件。来自注册表的物品名仍受服务端语言影响，FTB 原始本地化组件尚无专门客户端翻译协议。

统一设置使用 `assistant-settings.html`，常规、语音播报和语音输入在同一文档内切换标签，仍只加载 `assistant.css`，复用 `AssistantInputScreen` 的原生 IME 生命周期；不带聊天输入框的页面不会注册消息补全或 Enter 发送。密钥使用 AUI 的 password 输入框，仅存本机。固定文本先在客户端翻译，再送入 TTS；语种默认跟随游戏语言，也支持自动或显式选择，Qwen3 使用 `language_type`，Qwen-Audio 使用 `language_hints`。播报页另有默认关闭的整句音频缓存开关。界面和当前通知各自持有语音 session：新回复替换旧朗读，关闭或切换界面即取消；通知超时、确认、操作或隐藏同样立即取消，不等语音播完再切换下一条。通知恢复和历史不重播，播放状态区分原版和 OpenAL 后备。中英文语言文件的键集合保持一致。具体参数、音色兼容与工具用法见 [语音合成与音色设计](tts.md)。

语音播报页的“合成语种”使用 AUI 原生下拉选择框，列出跟随游戏语言、自动识别及全部支持语种，选项名称使用客户端本地化。选择后立即自动保存到原有语言字段；未填写 API Key 时沿用禁用逻辑。下拉框沿用唯一的共享 CSS 的字体、边框和焦点样式，弹出选项使用 AUI 原生弹层。

同页的“播报任务详情”“播报任务奖励”“播报任务背景”复用共享 `assistant_switch`，修改后立即自动保存，默认开启详情与奖励、关闭背景。详情关闭只读名称和奖励；开启后追加要求，背景还需单独开启且通过服务端叙事筛选。空说明、纯操作解释或不确定内容不作为背景播报，按任务唯一 ID 与语言持久化筛选结果。轮到当前语音 session 时按可信任务 ID 请求只读文案，模型回包不写入对话或替换卡片，不重置通知动画。物品名通过原版 Component 在客户端展开；可选目标与数量范围独立格式化，原有物品小卡片和 tooltip 不变。

系统文语气、提示词与公开参考来源见 [文案与提示词](system-voice.md)。UI 固定模板负责结算通知，模型只填写受限的签到选择理由；不会为语气额外增加模型轮次。

设置页的历史、外部 AI、自动朗读、通知音效、音频缓存、语音输入和识别后立即发送统一使用共享 `assistant_switch` 拨动开关样式，包含滑块位移、开关配色、焦点和禁用状态。“通知音效”位于语音播报页顶部，默认开启且无需密钥，与自动朗读独立；关闭后正文直接播报，连续通知仍不重复提示音。切换后立即写入 `SpeechConfig.notificationSoundEnabled` 并保存，旧配置缺少该字段时默认开启。底层使用 `button type=button role=switch`，避免 AUI 原生 checkbox 绘制与轨道叠加；不再使用透明 checkbox 覆盖。`AssistantView.bindSwitch` 统一处理点击、禁用检查和状态切换，`switchChecked` 以 `aria-checked` 同时驱动样式、辅助语义和表单读取。按钮支持 Enter / Space 激活，轨道与文字不接收指针，整行按钮可点击。所有标签修改后自动保存，TTS 仅保留试听和停止按钮。其他界面可复用同一结构与 CSS，不另加样式表。完整/简约模式仍使用分段按钮。

本轮仅检查模板结构、ID 绑定、资源路径与语言键，未运行游戏渲染。实际尺寸、滚动、输入焦点及不同 GUI 缩放仍需用户指定范围后进行客户端验收。
